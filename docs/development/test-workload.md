# 门禁测试负载与夹具成本（issue #498）

本页记录 [issue #498](https://github.com/hailingu/PlotWeave/issues/498) 的测试负载分析、修复范围和验证证据。目标是在正常开发机负载下减少不必要的测试工作，保持真实行为断言和完整质量门；先检查慢用例及场景合理性，再决定机制。

## 范围与判断标准

纳入 `pre-push-refs`、`gate-tree-marker` 和 `sonar-quality-gate` 的夹具成本。保持完整并行 Vitest 入口、现有用例、超时和断言；不修改生产钩子、扫描器、覆盖率地板或新代码问题条件。路由 / 标记矩阵的门禁边界使用探针，完整流水线仍由专属套件与选定 Git 集成用例执行。Git 和信号测试需要本机进程查询、进程组信号权限，受限沙箱导致的身份查询失败不能作为本问题的负载证据。测量统一使用仓库固定的 Node 24.18.0。

仓库所有者于 2026-10-03 选择「优先日常增量构建，记录冷构建边界」作为稳定性验收范围。并发负载使用已缓存依赖、只重编译 PlotWeave 包的真实离线 Cargo 检查；全依赖冷编译同时运行完整覆盖率不纳入此次通过条件。

| 完整覆盖率套件与正常 Rust 检查并发 | 连续运行完整 `npm run test:coverage` | 测试可靠完成、LCOV 行覆盖率仍 ≥80% | 测试入口和生产质量门不变 | 同机前后耗时、连续运行及真实 Rust 负载记录 |

本次不改变应用生命周期、存储、重试或 IPC 契约。多个测试 worker 分别拥有工厂；场景副本不共享模板的可变状态。非 Unix 和跨机器耗时未覆盖，不以墙钟硬阈值作为新回归测试。

## 测量与结论

基线为本地 `dev` 的 `ad4d79e`，本轮测试在同一台 macOS 开发机、Node 24.18.0 / npm 11.16.0、Rust 1.95.0 上执行。受限沙箱试跑与 Node 22 试跑不作为前后性能比较依据。

有效基线命令为 `npm run test:coverage -- --reporter=json --outputFile=<临时报告>`，187 文件 / 2841 项全部通过；`/usr/bin/time -l` 报告墙钟 **150.93s**、用户 / 系统 CPU **111.49s / 36.36s**。下面的文件耗时是并行文件各自的测试跨度，不能相加当作总耗时。

| 文件 / 用例 | 基线耗时 | 判断与取舍 |
| --- | ---: | --- |
| `pre-push-refs.test.ts`，43 项 | 149.64s | 真实 Git 路由、worktree 清理有必要；每个路由维度反复执行门禁内部全流程，额外成本没有验证新的路由不变量 |
| `gate-tree-marker.test.ts`，26 项 | 97.77s | 多种 Git 命令的钩子触发与标记归属需要真实 Git；相同门禁内部流程不必逐个重测 |
| `sonar-quality-gate.test.ts`，48 项 | 93.18s | 凭据、覆盖率地板、失败、锁和记录是该套件拥有的不变量，保留真实流水线；把检查根改成最小真实测试仓库 |
| `check-file-size.test.ts`，80 项 | 23.84s | 真实 Git 索引、对象协议和工作树边界有独立意义；没有把整组边界简单当成压力测试删除 |
| 清理后谎报失败 / 实际残留 | 4.08s / 2.52s | 不需要在判断清理诊断前再重跑全段流水线；继续实际创建和删除 worktree，保留原警告与目录断言 |
| 总字节量超过旧批量缓冲区（两个 6MiB 文件） | 282ms | 是总字节边界回归，输入规模超出典型手写源码；成本不构成此次主瓶颈，保留 |
| 8000 个同级 CSS `var()` | 14ms | 是栈溢出回归，规模不代表通常的样式；没有削减它的耗时收益依据，保留 |
| 100000 行 LCOV，79.998% 显示为 80.00% | 1.31s | 极值用于验证取整不能误放行，保护覆盖率比较契约；保留 |

复用播种历史、隔离检查根后，单跑脚本套件仍耗时 152.35s。它和完整 coverage 基线的口径不同，不能直接计算前后收益；该阶段没有提供足够的总耗时改善证据。随后按不变量所有者收敛重复流水线：路由 / 标记矩阵默认使用 `gate-routing-probe`，它执行真实 Git 查询、记录实际分析根的树和 HEAD，并受控透传失败；计数接口改名为 `gateRuns`，不把探针调用误称为扫描器执行。

完整集成保留情况：

- `pre-push-refs` 的真实 npm 凭据 / 超时、继承外层根的快路径、历史树规模政策、非检出分支、脏树、失败、Git 定位环境、多 ref，以及四个信号清理用例显式使用 `fullGate: true`。
- `gate-tree-marker` 的根隔离、记录树一致性、提交后推送物化、失败阻止 revert 继续使用完整流水线。
- `sonar-quality-gate` 所有原有用例仍运行真实脚本与真实静态检查入口；外部 npm / Cargo / Sonar 替身模式不变。新增根隔离回归还在自己的测试仓库放入超限源码，证明实际静态检查先失败、后续覆盖率 / 扫描不运行、既有记录不被追加。
- 工厂隔离回归验证首个副本的新 Git 对象、引用、索引和未跟踪文件不污染后续副本；失败播种不会缓存半成品。探针回归从另一个仓库启动，核验指定分析根和成功 / 失败记录边界。

这使场景规模服务于被测行为：测试 worktree 清理时仍创建真实 worktree，测试完整门禁时仍执行完整门禁，而相同路由维度不重复验证其他套件拥有的全部内部条件。

增量负载试跑还暴露了安装超时用例的时序假定：它把真实 npm 启动、lifecycle 启动和后代就绪全部压进 1 秒，却要验证后代忽略 TERM 时的清理。npm 未在期限前启动后代时，测试读不到 PID 文件，无法验证原目标。现在在独立测试进程中控制安装监督器的期限时钟：使用正常 300 秒配置，等后代安装 TERM 处理器并写出 PID 后触发真实期限回调，保留真实 npm、进程组信号、1 秒 KILL 升级和全部结果断言。若 20 秒仍未就绪，测试报告就绪失败并通过同一监督器回调清理，而非直接退出留下安装组；此保护路径未单独做延迟故障实验。

安装输入的播种提交也不再执行一次无关门禁；随后作为验证入口的实际 `git push` 仍启用真实钩子与完整流水线。这是测试私有仓库的准备步骤，不改变当前工作区的钩子配置。

## 资源证据与边界

| 维度 | 证据 / 适用范围 |
| --- | --- |
| 并发与排队 | 使用完整并行入口；记录单文件跨度与最慢用例。未做并发梯度、吞吐拐点或调度排队分布测量，不声称定位到某一种调度器瓶颈 |
| CPU | 记录命令用户 / 系统 CPU；仅据高占用无法判定根因。跨层重复进程由实际夹具调用链和收敛前后运行交叉验证 |
| 内存 / GC | 基线 `time -l` 最大 RSS 为 477921280 字节，这是命令报告口径，不代表所有并行进程的 RSS 总和；未做 GC trace，未发现可据此认定的内存瓶颈 |
| I/O | 场景确实写 Git 仓库和临时 worktree；复制模板仍保留独立对象。没有 I/O 延迟 trace，不把写盘量直接当成根因 |
| 锁 | 每场景独立门禁锁；占锁 / 恢复测试保留。并发 Rust 检查使用独立临时 target，避免把共享 Cargo target 排队当成应用负载 |
| 连接池 / 下游 | 这些脚本测试没有真实远程连接池；npm registry / Sonar / 覆盖率工具仍受控替身。负载实验使用离线 Cargo 编译缓存，不引入网络抖动 |

全依赖冷构建试验中，Rust `cargo check --all-targets --offline` 用时 **45.03s**，并发覆盖率用时 **135.09s**、13 项超时；该阶段还未修复上述 1 秒安装时序假定。一次增量试跑的 Rust 检查用时 **6.96s**，覆盖率用时 **131.69s**，唯一失败是该安装用例读不到 PID。二者用于解释负载边界和定位时序问题，不作为最终版本的通过证据。最终版本不再复测冷构建并发，不能据此声称该边界已解决。

## 修复后验证

首次完整 coverage 试跑（新增探针独立回归前）188 文件 / 2844 项全部通过，耗时 **109.52s**。补齐安装时钟的失败清理后，最终测试实现固定，连续五次完整覆盖率均为 **189 文件 / 2846 项通过、0 失败**：

| 轮次 | 并发负载 | coverage 墙钟 | 用户 / 系统 CPU | Rust 检查结果 / 与 coverage 重叠时间 |
| --- | --- | ---: | ---: | --- |
| 1 | 真实 Rust 增量检查 | 113.78s | 98.54s / 28.76s | 通过 / 5.69s |
| 2 | 真实 Rust 增量检查 | 102.75s | 99.04s / 28.44s | 通过 / 3.78s |
| 3 | 无额外测试负载 | 96.71s | 98.03s / 28.04s | 不适用 |
| 4 | 无额外测试负载 | 103.04s | 96.88s / 27.66s | 不适用 |
| 5 | 无额外测试负载 | 98.52s | 98.13s / 28.42s | 不适用 |

五轮墙钟中位数 **102.75s**，范围 **96.71–113.78s**，比单次基线 150.93s 下降约 **31.9%**。三套件各自跨度的中位数为 `pre-push-refs` **101.31s**、`gate-tree-marker` **53.41s**、`sonar-quality-gate` **78.67s**；仍不能相加为墙钟。两个原清理警告用例的中位数为 **0.98s / 1.05s**，真实安装超时回归为 **3.04s**。基线只有一次，不能把这组数据当成统计显著性结论或跨机器、最坏负载保证。

每轮执行 `npm run test:coverage -- --reporter=json --outputFile=<临时报告>`，由 `/usr/bin/time -l` 记录耗时。前两轮在 Rust 源码临时副本执行 `cargo check --all-targets --offline`，设置独立 `CARGO_TARGET_DIR`，且每轮先对该临时 target 执行 `cargo clean --package plotweave --target-dir <临时target>`：重编译应用包、复用依赖，避免把空操作当成增量负载，也不影响原工作区的 Cargo 缓存。最终 LCOV 为 **6806 / 6934 行 = 98.154%**，全部五轮均通过配置中的 80% 行覆盖率地板。

验证入口与结果：

- 仓库根执行 `npm run check:size && npm test -- scripts`：**13 文件 / 260 项通过**。此轮与另一次完整 coverage 附加试验重叠，脚本测试耗时 154.51s，coverage 169.41s；后者也全部通过，但没有混入上表的日常负载耗时。
- 仓库根执行 `npm run format:check && npm run lint && npm run check:size && npm run typecheck:strict`：全部通过。文件额度检查为 525 个维护文件、57 个排除文件；本次三个测试文件均低于 1800 行，新夹具 / 探针源文件低于 800 行。文档最后补录后另做 Prettier 与差异空白检查。
- 工厂复用和根隔离的新增回归均先观察预期失败，再通过；探针的真实 Git 根选择及成功 / 失败记录边界回归通过。矩阵中的原 Git 操作、安装、信号、锁与记录用例均由脚本和完整覆盖率运行验证。
- 在独立临时副本的成功清理路径额外输出 `[PRE_PUSH_WORKTREE_RESIDUE]`，原「实际已移除，不输出残留警告」用例在 `not.toContain` 处正确失败；最终源码的定向变异复核耗时 3.93s。保留实际残留时一次警告和目录存在的原断言。
- 文档及相对链接做结构化复核；该文档范围没有配置语义自动检查。无产品源码、前端配置、Rust 源码或生产钩子变更，未执行对应构建 / Rust 全路由检查。上述负载验收阶段未运行真实 SonarQube 全门禁或生成真实 Rust 覆盖率；后续提交、推送仍须另行执行完整门禁，结果由对应门禁运行及 PR 验证记录提供。

验收覆盖了所选日常增量构建场景。冷构建并发、跨平台 / 跨机器、20 秒未就绪保护路径及前述未做的资源 trace 保持明确验证边界。临时编译 target、仓库副本和 coverage 产物在记录结果后清理，保留的证据为本页命令、基线提交、不变量与结果摘要。
