## 七、资产模型

### 7.1 两个作用域

**Swift 原生保存与失败边界（[PR #526](https://github.com/hailingu/PlotWeave/pull/526)）**：当前原生服务由 `NativeProjectStore` 直接保存，`NativeProjectEnvelope` 校验完整信封／资产形状，`NativeDirectory` 按绑定目录句柄执行文件 I/O；原生应用不调用下文的 Rust 服务。项目保存前后均复验真实媒体。下文“失败整份拒绝”指提交前的形状／实路径复验：它不能更新文档。rename 已提交后，父目录持久性屏障或写后资产复验失败仍返回错误，文档可能已是新内容；这与[持久化 §10.5](persistence.md#105-rust-持久化命令tauri-commands)明示的两类失败一致，不是媒体与项目 JSON 的跨文件回滚事务。失败回执不能用于推断磁盘未变，也不能通过删除复验或忽略同步错误伪装成功。正常项目保存、媒体写入和删除由同一 Swift actor 串行；单实例范围及跨进程替换的保留边界见[§10.0](persistence.md#100-swift-原生落地与保留差异)。

- **项目资产**：归属于某个项目，文件存于项目目录内，`project.json` 的 `assets.byId` 只索引本项目资产。项目是**自包含**的——导出、备份、移动项目目录不会丢失任何引用。
- **个人资产库**：跨项目复用的素材（角色立绘、参考图、常用模板），存于应用级 `library/` 目录，由独立的 `library.json` 索引，不进任何 ProjectDocument。

两个作用域共享同一个引用结构：

```ts
/** 资产引用：媒体本体是文件，文档只存引用。 */
interface AssetRef {
  id: string
  relPath: string            // 项目资产相对项目目录；库资产相对 library/ 目录（维持既有磁盘格式：库条目写作 assets/<文件>——变更基准会让既有资产全部解析失效）。解析目标必须落在专用资产子目录内，安全约束见下
  mime: string
  source: 'upload' | 'generated'
  createdAt: string
}
```

**节点媒体生命周期归属（[issue #504](https://github.com/hailingu/PlotWeave/issues/504)，已实现）**：图片产物与分镜引用共用 `useAssetMedia`，仍经 `projectAssets.mediaUrl(projectId, assetId)` 解析项目媒体；请求清理后丢弃迟到成功/失败结果，依赖只取项目与资产 id。节点保留按资产 id 重挂载的首帧清旧图语义、原样式与局部错误占位；不新增自动重试、URL 释放或持久化契约。[状态矩阵与重复度实测](../development/duplication-policy.md#关键状态与不变量矩阵)记录本次验证。

**后端媒体能力归属（[issue #146](https://github.com/hailingu/PlotWeave/issues/146)，已实现）**：按项目资产管线、图库命令、协议适配器、纯策略和文件系统能力区分依赖；错误类型所在的 `library::error` 是独立契约，引用它不等同于调用图库命令。`media_protocol` 独立持有跨作用域的 `pwmedia` 请求处理与 `get_asset_media_url`，单向调用 `assets::project_media`、库索引和恢复能力；图库命令不再包含协议适配器。`media_format` 是无 IO 的扩展名叶子策略，供 `assets` 与 `library` 直接消费：导入仍优先使用合法的短文件扩展名，其余按 MIME 回退；生成产物仍仅按原有 PNG/JPEG/WebP/GIF 映射扩展名，其他类型回退 `bin`。`library_fs::open_library_asset` 统一持有库文件的句柄链打开、普通文件与 Unix 身份复核，供项目导入和协议读取共用。没有兼容性反向 re-export；IPC 名称、URL、磁盘格式、锁与读取许可生命周期不变。`src-tauri/tests/media_format_leaf.rs` 在不声明其他应用模块的测试 crate 中直接编译生产叶子，并验证两种扩展名策略；其余能力的方向按生产引用核对，本单未引入全仓 Rust 模块图检查。

**活动资产与隔离区边界（[#649](https://github.com/hailingu/PlotWeave/issues/649)、[#650](https://github.com/hailingu/PlotWeave/issues/650)，已实现）**：基础 relPath 词法与活动索引判定分层；NUL 不是可表示的文件名，三栈均拒绝。活动 AssetRef、保存边界与媒体入口还拒绝任意精确 `.trash` 组件；`.trashcan` 等普通名称保持有效。Rust 与 Swift 的加载验证对保留隔离区引用一律返回坏资产键，无论文件存在与否，且不打开隔离字节；基础词法非法或字段缺失仍交给 Web 归一化隔离。加载本身不修写原文件，唯一修复点仍是前端：发出带资产键的警告、从活动索引隔离该条目，按既有保存协调写回后即可继续编辑。直接提交未修复的隔离引用，两宿主都整份拒绝且不改原项目文件。此修复不删除隔离媒体、不改变删除日志及恢复语义，也不把库隔离事务当成活动文件路径。

路径和规范 MIME 的判定由同一份[版本化 JSON 向量](../../crates/plotweave-core/testdata/asset-contract.json)分别在 Rust／Swift 消费，Web 通过实际项目归一化消费活动路径用例；维护和运行方式见[共享资产契约向量](../development/native-coverage.md#共享资产契约向量)。MIME 向量只锁定既有词法，不替媒体响应类型或下载策略作决定。

**复制与导入的活动命名空间（[issue #887](https://github.com/hailingu/PlotWeave/issues/887)、[issue #888](https://github.com/hailingu/PlotWeave/issues/888)）**：项目复制在 Rust 与 Swift 两栈均逐层排除精确 `.trash` 条目，不复制隔离媒体或 receipt，源证据不变；`.trashcan` 等普通目录与活动资产仍正常复制，排他目标、no-follow 与失败回滚保持。库→项目导入在索引归一化之外也使用活动 relPath 谓词复核，拒绝任何 `.trash` 组件；该项为冗余防御一致性，现有归一化本已阻止隔离条目进入导入查询，不宣称修复当前可达的越界导入。

**AssetRef 的 JSON 边界完整校验**：导入、Agent/MCP、磁盘项目文档与 `library.json` 中的 TypeScript 形状均已擦除。进入活动索引前必须确认条目是普通对象；`id` 满足 §8.1 的字符串 id 值域，`relPath` 是非空字符串并满足下述路径安全约束，`mime` 是去首尾空白后由两个非 `*` RFC 9110 token 组成的具体 `type/subtype` ASCII 媒体类型（索引不保存参数，统一小写），`source` 严格等于 `upload` 或 `generated`，`createdAt` 是带显式 `Z` 或 UTC offset、可解析且表示有效时刻的 ISO 8601 字符串并统一落为 UTC `toISOString()`。`set_asset` 的纯模型校验对完整形状执行该规则；此外公开 dispatcher 必须在调用内部 reducer 前，经 Rust `validate_project_asset(projectId, asset)` 以受信项目/资产根句柄逐组件 no-follow 打开 `relPath`、确认目标是资产根内普通文件，并只采用 Rust 返回的规范化 AssetRef。形状或真实路径任一失败时不得进入活动文档、undo/redo 栈或脏标记；导入/生成、Agent/MCP、撤销/重做与 batch 同样不得绕过。`save_project` 在任何临时文件或时间戳写入前对 `assets.byId` 全量执行同一 Rust 实路径复验，防止预检后目录项被替换；失败整份拒绝且不更新索引。加载项目时，`assets.byId` 的 Record 键/id 先按 §11.1 的共同规则修复；加载资产库时，旧数组格式先按 §7.2 的兼容迁移转换为目标 Record，再执行同款键/id 修复。随后，合法但未规范化的 MIME 大小写/空白与带显式时区的时间戳表示可确定性规范化并警告，其余无法无歧义修复的条目隔离并警告，引用按 §8.2.3 标记悬空。库侧即使另有分类字段归一化，也必须执行这些共享字段规则，不能因 `relPath` 合法就跳过基础形状。

**relPath 安全约束**：relPath 必须是纯相对路径（禁止绝对路径），其**基准**为项目目录（项目资产）或 `library/` 目录（库资产）——维持既有磁盘格式（库条目写作 `assets/<文件>`），基准变更会让既有资产解析成 `library/assets/assets/<文件>` 而全部失效。解析目标必须位于**专用资产子目录**内（项目 `assets/`、库 `library/assets/`，§10.1），且不得进入保留的库隔离目录 `library/assets/.trash/`（该目录及其随机名称永不进入 AssetRef、媒体 URL 或孤儿候选）：控制文件（`project.json`/`library.json`/`index.json`）位于子目录之外——`"library.json"` 这类条目词法合法、解析后也在库目录内，但目标不在 `library/assets/` 内即非法，`delete_library_asset`/`remove_file` 之类的按路径操作由此永远触达不到索引自身；含 `..` 上跳段使解析目标越出子目录同样非法。词法规范化不足以兜底：资产目录内若存在指向根外的符号链接，`assets/link` 词法合法、不含 `..`，真实路径却已越界——因此校验以**真实路径包含关系**为准：对资产子目录与目标路径做 canonicalize（解析符号链接）后判定目标仍位于子目录之内，越界即非法；新增资产（目标文件尚不存在、无法 canonicalize）时拒绝路径各级中的符号链接，或对最近已存在祖先做 canonicalize 后拼接校验。**信任链必须从应用数据根逐级建立，不能把待校验的基准目录自身当作最外层锚**：先 canonicalize Tauri `app_data_dir` 作为受信根并确认 `projects/` 与 `library/` 的 canonical 路径仍位于该根内，再确认 `{projectId}/` 的 canonical 路径仍位于 canonical `projects/` 内，最后才确认项目 `assets/` 位于该项目目录内、`library/assets/` 位于 canonical `library/` 内；任一现存中间目录是指向其父级受信根外的符号链接，均拒绝整个对应资产区并记录警告。目录尚不存在时只能通过已验证且无符号链接的父目录创建，创建后重新 canonicalize 并复核逐级包含关系。由此即使项目目录与其 `assets/`、或 `library/` 与 `library/assets/` 一起指向同一外部树，也不能以“根与目标彼此包含”为由通过校验。**分层执行**：词法校验（纯相对、解析目标在子目录内）前端模型层可执行；上述逐级真实路径包含判定只能在可访问文件系统的 Rust 层执行——webview 模型层无法自行解析本机符号链接。Rust 在 `load_project` 与资产命令内对每个 relPath 做 canonical 校验并把非法条目清单随加载结果返回，前端归一化消费该清单隔离条目；库侧 `list_library_assets`/`delete_library_asset` 在 Rust 内同款校验。这是 §7.1「项目自包含」与备份/移动完整性的前提，也是信任边界校验（防解析或复制时逃逸资产根）：`set_asset` 命令边界拒绝非法值，归一化对脏数据隔离该索引项并记录警告（引用该资产的字段按 §8.2.3 悬空展示）。**库索引入口同款约束**：`library.json` 不走 §11.1 项目文档归一化（它不是 ProjectDocument），且可被手工修改或损坏——读取库索引（`list_library_assets`，§7.2 启动时全量载入）时对每个条目应用同款校验（含真实路径包含判定），非法条目不进内存索引并记录警告。仅在列表入口过滤不足以兜底：`delete_library_asset` 等操作会重读或消费索引中的 relPath，而目录项可能在列表校验之后、实际读删之前被替换（TOCTOU）。**canonicalize 只用于加载筛查、包含关系诊断与无句柄平台上的拒绝性兜底，绝不是后续文件 I/O 的授权凭据；缓存“本会话已验证”的 relPath 同样不构成授权，本文不再允许二者作为实际操作的替代方案。**凡按 relPath 触达项目或库资产文件的入口（导入、创建、读取、媒体响应、复制、移动、删除与清理）均由 Rust 在该次操作内从已验证的应用/项目/库父目录句柄出发，以 no-follow 语义打开并持有专用 `assets/` 根目录句柄；把词法校验后的 `assets/<子路径>` 去掉固定首段后，逐组件以相对目录句柄继续打开，拒绝空段、`.`/`..`、符号链接、非目录中间项及越界，整个句柄链保持到操作结束，不得在校验后退回原始绝对路径或字符串拼接路径。读取以最终父目录句柄相对 no-follow open，并在已打开句柄上确认普通文件后流式读取；删除不得只凭最终组件名称调用 `unlinkat`：no-follow 只能阻止跟随符号链接，不能证明该名称仍绑定此前打开的普通文件。库资产删除必须先按 §7.2 把经身份核验的目录项原子移入保留的私有隔离区，再提交索引；提交后只允许以仍绑定该已打开文件身份的平台原语清理隔离项，平台不能提供等价保证时保留隔离项并返回 `cleanupPending`，不得退化为按名称删除。创建/导入在句柄下排他创建随机临时文件并以句柄相对 rename 落位。Rust 文件系统适配层必须在各平台为路径解析、读取、创建与原子移动提供与 POSIX `openat`、Linux `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)` 同等的“根句柄绑定 + 逐组件不跟随”保证；普通 `unlinkat` 只约束删除发生在受信目录内，**不满足**库媒体的文件身份绑定清理，后者必须使用 §7.2 的更强平台原语或保留 `cleanupPending`。相应能力缺失时拒绝该阶段，不得降级为 check-then-use。媒体展示也不得把本机绝对路径或 relPath 交给前端 `mediaUrl` 拼接/通用文件协议：前端只获得含 scope + assetId 的 opaque asset URL，Rust 自定义协议处理器在**每次请求**重新从当前规范化索引解析 id，并通过上述句柄链读取后返回字节；索引内存快照可以减少 JSON 重读，但永远不能跳过这一步文件系统能力校验。由此目录项在列表后被替换也无法让任何项目或库入口触达资产根外文件。

控制文件不适用“只拒绝对应资产区”的降级：项目目录或库目录的任一级信任链失败时，必须按 §10.2 在任何控制文件 I/O 前拒绝整个项目或库操作；不能先读取 `project.json`/`library.json`，再仅把资产标为不可用。

**媒体访问落地（#9、#26、#31）**：项目与库媒体均已接入 `pwmedia`，`get_asset_media_url` 只接收逻辑 scope 与 assetId；`library_dir_path`、`project_asset_path` 已移除，通用 `assetProtocol` 已停用且 scope 为空。#9 曾采用的资产子目录白名单是历史过渡方案。项目资产 id 在 URL 段中以 UTF-8 字节的十六进制编码保留完整值域；这只是编码，不是加密。

项目媒体以磁盘 `assets.byId` 为权威；导入/生成后尚未防抖保存的资产由 Rust 在落盘管线登记到应用持有的 `PendingProjectAssets`，在索引空窗期供解析。加载时空白键重发通过 `register_project_asset_alias` 登记“新 id → 原磁盘键”别名，别名不携带路径，不复活已删除条目；项目控制文件缺失时拒绝服务并清理该项目登记。每次媒体请求仍重新打开并复验文件。当前 Tauri 响应采用有界缓冲交付，而非流式 body：库媒体上限 20 MiB、项目媒体上限 256 MiB，并发闸门为 4，许可持有至响应交付。超过 256 MiB 的项目文件可能可保存但无法预览，这是已登记的读取边界；不能把生成结果的 32 MiB 上限套在所有历史项目媒体上。

### 7.2 库资产的分类与编组

**Web 资产面板回执呈现（[issue #700](https://github.com/hailingu/PlotWeave/issues/700)）**：面板逐个显示 `put` 已确认的成功条目；后续导入失败不隐藏或撤销这些结果，错误包含失败文件名。确认删除后保持既有乐观隐藏，只有 `remove` 成功才回收缩略 URL；拒绝时按资产 ID 恢复门面最近持久化条目（无快照时使用打开确认框前保留的已落盘名称锚点，避免改名与删除均拒绝后恢复乐观名称），保留错误与显式重新确认入口，不覆盖并发新增项。初始列表尚未落定时暂停 Web 文件导入，之后才接纳新变更；缩略 URL 的在途 token／句柄由挂载面板独占，删除成功与卸载会作废迟到回执并回收 blob，失败删除保留有效请求。该显示恢复不回写库、不重发变更，不改变同资产队列、提交不确定性及下述宿主日志恢复合同；Swift 原生图库模型的失败重读继续沿原规则。门面在导入、元数据更新、删除每次成功落盘后发布变更通知（issue #802）：存活面板实例据此失效重读列表，旧实例在面板重挂载后落定的成功结果即时对当前实例可见；重读保留在途/未解决失败意图的本地投影与乐观隐藏的删除行，仅采纳最新一次发出的读取（界面行为见[界面设计 §8.1](../ui-design.md#81-资产库面板按影视美术部门分类)）。

**库媒体瞬时读取失败（[issue #883](https://github.com/hailingu/PlotWeave/issues/883)）**：原生库操作的媒体筛查对 `PW_STORAGE_ERROR`（包括 EMFILE、EIO、EACCES）保留索引条目，返回可见 warnings 并记录 `PW_LIBRARY_MEDIA_UNAVAILABLE`，不因此设置 changed 或持久化删除。确证缺失／不可信文件仍沿既有隔离路径处理。原有索引归一化或恢复写入不因该诊断失效；不能将一次打开失败解释为媒体字节已丢失。

**Swift 原生批量导入呈现（[PR #526](https://github.com/hailingu/PlotWeave/pull/526)）**：原生系统选择的文件逐个沿 `NativeLibrary` 落盘，不新增整批事务或自动重试。后段读取或导入失败时，`NativeLibraryModel` 重读权威列表，显示已提交的真实资产并保留失败提示；其他写入口共用失败重读。列表恢复也失败时保留最后有效快照，同时报告原错误与刷新失败，不制造空索引。关闭使旧任务失去发布权限；原生选择注入仅供本机组合和隔离测试，不增加 Web 文件路径入口。见[矩阵 R16–R17](../swiftui-react-flow-pr526-fixes.md)。 所选 URL 使用 no-follow、非阻塞打开，随后由 `NativeMediaFile` 在实际 descriptor 上核验普通文件；FIFO 不等待 writer、目录／symlink 不读取，失败回到同一列表恢复路径，既有普通文件字节上限与取消保持（[PR #526 R26](../swiftui-react-flow-pr526-fixes.md)）。 接纳导入或直接变更的展示批次还同步登记应用级退出资格（[issue #529](https://github.com/hailingu/PlotWeave/issues/529)）：批次落定——含失败重读与 sheet 取消完成——先于退出事件投递与最终批准，最终批准复查仍有在途批次时拒绝 `PW_NATIVE_LIBRARY_PENDING` 并保留重试；已提交项与 R38 恢复保持，不自动重放或回滚，只读刷新不设资格，合同详见[桥的原生图库批次退出资格](../swiftui-react-flow-feature-parity.md#桥合同)。

**Swift 导入恢复（[PR #526 R38](../swiftui-react-flow-pr526-fixes.md#导入媒体与索引失败恢复r38)，所有者于 2026-10-13 授权）**：`NativeLibrary` 在持有 actor／flock 的同一操作中先校验候选索引并完成必要原件备份。媒体临时文件写入及 fsync 后，从已打开 descriptor 取得精确 `(dev, ino)`；在最终媒体 rename 前，将 assetId、relPath、身份、随机隔离名及 `importPending: true` 耐久登记到既有 `asset-delete-journal.json` 对象。登记仍受 512 KiB 投影和 1 MiB 限读／写预算约束，日志及父目录未同步成功时不得落位媒体；`.trash` 仍须为同文件系统的受信目录。随后媒体排他 rename／资产父目录 fsync、完整索引原子提交／库目录 fsync，才按已提交索引退役导入记录。索引提交或收尾失败原样返回，不把失败等同未提交，也不自动重放导入。

下一次列表、任何库写入、媒体打开或 `source` 项目复制前共用日志恢复。导入记录须有完整、无需规范化的权威索引；损坏、异型成员、迁移挂起或任一活动引用无法实际打开时，保留记录／媒体，返回证据诊断并暂停所有库写入，既不重发未落定身份，也不自动回写过滤后的局部索引。恢复核对所有活动条目的真实媒体身份，不只比较 relPath；已被任何活动引用持有的媒体保留；中断恢复后仍存在的同身份隔离副本继续联合计入可见摘要，不因活动引用出现而丢掉保留统计。判定前同步当前控制索引及相关媒体／目录，避免将索引 rename 后屏障失败误判为未提交。只有确认无活动引用且原路径仍绑定登记身份时，才复用身份核验、no-replace 隔离和联合统计提交：媒体进入 `.trash`，事务退役后以一条 routine `cleanupPending` 摘要显示保留数和字节量，反复恢复不重复累计。落位前中断、最终媒体和隔离名都不存在时，可同步目录后退役空事务；原名被后来文件／symlink 占用则保留证据，绝不覆盖或删除占用者。

恢复移动或日志提交再次失败时，原记录或完整新统计仍可重读；未解决导入阻止继续写入，避免恢复失败下反复累积不可见媒体。原生表单沿 R16–R17 的失败重读显示这些诊断并保留原错误。平台仍无身份绑定删除原语，因此物理媒体保留到人工核对清理，不能把隔离收敛宣称为磁盘空间已释放。无日志的历史孤儿不扫描、不猜测；Tauri 历史导入和待实现收藏仍保持下述保留边界，新 Swift 应用使用独立开发数据根，不将本协议宣称为跨旧宿主迁移。物理断电、真实满卷和手工隔离区清理未实测；确定性阶段故障及真实目录权限／占位回归见 R38 矩阵。

**落地状态（#17、#25、#29）**：锚定句柄访问、1 MiB 库索引限读、脏条目隔离、日志驱动删除与恢复、Record 迁移、完整归一化、组命令及库命令重命名均已合入 `dev`。库操作由进程内互斥锁与跨进程文件锁串行化；跨进程锁文件 `.library-op.lock` 自身的打开遵循本域 no-follow 归类纪律（[issue #721](https://github.com/hailingu/PlotWeave/issues/721)）：先 `symlink_metadata` 归类，既有符号链接或非普通文件保护性拒绝，仅确证缺失才以 `create_new` 首建，跨进程首建竞态经重新归类收敛。列表及写入前先恢复未完成事务，返回 `warnings`/`cleanupPending`，只读告警态暂停写入。平台缺少身份绑定清理能力时仍保留隔离文件，不把“事务已实现”解释为“必定立即物理删除”；已核验清理项在下次恢复折叠退役（[issue #359](https://github.com/hailingu/PlotWeave/issues/359)），日志不随生命周期累积。库操作锁的中毒后行为为可验证恢复（[issue #145](https://github.com/hailingu/PlotWeave/issues/145)）：锁不守卫内存状态，磁盘一致性由本节日志可恢复提交协议独立保证。平台编译边界（[issue #546](https://github.com/hailingu/PlotWeave/issues/546)）：本协议官方仅支持 macOS；非 Unix 目标保持可编译（仅提供源码，Windows 等由使用者自行构建，见 README 平台声明），运行时身份原语（`(dev, ino)` 路径/隔离项身份核验）与目录持久性屏障按能力缺失显式拒绝、删除入口在无身份平台拒绝，绝不基于猜测身份移动或删除媒体。

资产库要回答"我有哪些人物/场景/道具的哪些视图"，扁平标签不足以表达（"三视图"是结构而非标签），因此采用结构化分类 + 编组 + 自由标签三层：

```ts
/** 资产视角：三视图/多角度/表情/定妆等结构化分类。 */
type AssetView = 'front' | 'side' | 'back' | 'three_quarter' | 'top' | 'expression' | 'turnout' | 'other'

/** 个人资产库索引项：在 AssetRef 之上带分类与组织信息。 */
interface LibraryAsset extends AssetRef {
  name: string
  kind: 'character' | 'location' | 'wardrobe' | 'colorlight' | 'reference' | 'other'  // 角色设定/场景设定/服化道/色彩光影/风格参考/其他
  view?: AssetView           // 视角；三视图即同一 group 下 front/side/back 各一张
  groupId?: string           // 同一主体的多视图编组，引用 library.json 的 groups
  tags: string[]             // 自由标签，补充 kind/view 表达不了的维度
}

/** 资产组：同一主体（如某角色）的多张视图/变体的集合。 */
interface AssetGroup {
  id: string
  name: string               // 如「女主·林晚」
  kind: LibraryAsset['kind']
}
```

- **完整库形状与加载归一化**：`library.json` 根值及目标格式的 `assets.byId`/`groups.byId` 必须是普通对象，桶成员也必须是普通对象；异型根按下述损坏索引恢复规则处理，异型桶或成员隔离并警告，均不得在字段检查前解引用。键/id 按上文兼容迁移及 §8.1 共同规则一致化后，资产先执行 §7.1 的完整 `AssetRef` 校验，再校验 `name` 是去首尾空白后 1–128 字符的字符串、`kind` 严格属于声明联合、`tags` 是至多 16 项的数组且每项是去空白后 1–64 字符并在规范化后唯一；`view` 存在时必须是 `AssetView`，`groupId` 存在时必须是 §8.1 合法字符串 id。组同款校验 `name` 与 `kind`；合法 name 保存去空白后的值，必填 `name`/`kind` 或 AssetRef 字段异型时整个条目隔离。可选组织信息允许安全降级：加载时 `tags` 非数组重置为 `[]`；数组成员先去空白，异型/空白/超长/重复项删除，超过 16 个规范成员时只保留文档序前 16 项；非法 `view`/`groupId` 剥离，均警告。组条目隔离完成后再解析资产 `groupId`：目标组不存在或组与资产的 `kind` 不同即剥离该引用并警告，活动库内始终保持同组同类。
- **损坏索引的局部恢复（[issue #137](https://github.com/hailingu/PlotWeave/issues/137)，已实现）**：`library.json` JSON 语法、UTF-8 编码或根形状损坏时，按已知的 `assets`/`groups` 桶提取边界可确认且能完整解析的成员，再执行既有字段和引用校验；正常条目继续支持列表、媒体访问、导入项目、编辑与删除，脏条目隔离并返回 `warnings`。按栈核对 `{}`/`[]` 的匹配类型，遇到错配立即停止扫描其后内容，仅提取此前已确认的完整成员；同样不猜测截断字符串或嵌套结构之后不能确认归属的内容。无法识别任何条目时返回带损坏提示的空视图；媒体文件不能重建名称、标签、组等索引权威元数据。损坏视图采用确定性的只读归一化，不生成未落定的新 id，读取不覆盖损坏原件。用户后续导入、编辑或编组等写操作，以当前可用视图为基线保存；替换前必须将原始字节耐久保存为同目录 `library-corrupt-<原始字节的 SHA-256 摘要>.bak`。同一原件失败重试时复用该备份：核对普通文件、实际字节一致并重新同步文件和目录（Unix）后才继续，避免相同副本随重试累积；原件变化则保留独立备份。备份创建、读取或同步失败，或同名备份类型/内容不符时拒绝继续，不覆盖异常备份。既有随机名备份保留，不自动迁移或删除。导入入口先完成候选索引校验与原件备份，再物化新媒体，最后提交索引，因此备份失败及其重试不会新增媒体；媒体物化失败不提交索引，已完成的备份保留。媒体成功后最终索引提交失败不因错误而盲目删除可能已提交的媒体；Swift 原生导入按上述 R38 日志恢复收敛，Tauri 历史路径保持下述孤儿保留边界。该备份用于保留恢复证据，不自动合并回库；损坏条目不因恢复而触发媒体清理。既有索引大小上限、文件类型和 IO 错误仍明确失败，不把这些错误当成空库。该备份内核已提取为 store 共用原语（`store::damaged_backup`；设置侧 `settings.json` 覆盖前同款接入，[issue #390](https://github.com/hailingu/PlotWeave/issues/390)），本侧语义、命名与诊断不变。
- **损坏索引与未完成删除（#137，已实现；收敛路径 [issue #389](https://github.com/hailingu/PlotWeave/issues/389)）**：删除恢复不能把局部索引缺失的 assetId 当作已提交删除。索引损坏且事务目标缺失时，先在日志耐久写入 `indexUncertain: true`，随后保留该事务的原媒体、隔离文件和日志，报告冲突及 `cleanupPending`；其他正常条目仍可使用和写入。索引恢复为**权威视图**（可解析且迁移可落盘）后，下次恢复复位该标记并按当前索引重新判定：索引仍引用 → 走回迁/未开始等既有收敛分支；索引已去项 → 按「删除已生效」收敛（原路径仍绑定预期媒体时重隔离，清理按身份绑定能力保留——身份核验一致的保留项随即折叠退役，见下条 issue #359）。资产不再因历史损坏永久 `conflicted`；索引再次损坏时**仍驻留日志的**条目按损坏规则重新置位，保守方向不变（已折叠退役的闭合事务不再置闩，见下条）。非权威期间一律保持冲突保守：索引仍损坏时告警指引修复 `library.json` 为可解析 JSON（人工修整，或经任意图库写入自动替换为修复视图）；索引可解析但迁移产物超限挂起（只读局部视图隔离了待重发条目，写路径拒绝同一视图）时，恢复判定同样不以其为权威，告警指引人工修整条目使迁移结果可落盘——修复后的图库操作均自动重新判定。标记写入失败或使日志超过原有 1 MiB 上限时，本次恢复在媒体操作前失败；所有日志写入都检查序列化后的大小。日志自身异型仍沿用全库只读告警规则。
- **已完成清理项的折叠归档（[issue #359](https://github.com/hailingu/PlotWeave/issues/359)，已实现；[issue #421](https://github.com/hailingu/PlotWeave/issues/421) 联合日志修订）**：受支持平台均缺少身份绑定删除原语，「索引已提交 + 隔离项身份核验一致」的终态事务此前永久驻留日志，每次恢复逐条核验、`cleanupPending` 逐条进响应，均随生命周期线性增长。现在这类条目在恢复按权威视图判定后折叠退役，逐条核验成本与列表响应大小与历史删除总数解耦；隔离项与媒体字节原样保留，折叠绝不按名删除隔离项。`cleanupPending` 为单条 routine 摘要，序列化为 `{"kind":"routine","message":"…","count":N,"bytes":B}`：结构化 `count` 供前端计数按条目求和，结构化 `bytes` 为隔离区字节量级（[issue #427](https://github.com/hailingu/PlotWeave/issues/427)），量级未知时省略；message 携带同值、量级与「整体移除 assets/.trash 后计数自动归零」指引，普通/证据条目不序列化这两个字段。
  - **退役与统计同次提交（#421）**：`library/asset-delete-journal.json` 根为 `{"entries":[…],"retainedCleanupCount":N,"trashBytes":B}`，未知字节量级时省略 `trashBytes`。折叠条目从 `entries` 退役、累计保留计数和字节量级通过 §10.2 的同一次原子替换及目录持久性屏障提交，不再先退役日志、后写旁路归档。rename 前失败保留完整旧快照；rename 后目录屏障失败仍返回 Err，但当前可见的新快照同时包含退役和统计，后续恢复不永久少计或重复累计。任何日志写失败均向调用方传播，包括格式迁移与整体清理后的统计归零，不把未完成的持久化伪报成已完成恢复。整趟恢复期间折叠条目保留在内存日志投影中，仅在收尾单次写盘统一退役；后续条目的重隔离预 rename 中间写不能提前持久化先前折叠条目的退役或本轮统计增量（评审 5346397307/5346509928）。事务追加、清理成功退役、`indexUncertain` 置位/复位和重隔离映射写均携带完整日志状态，保持已有累计值。
  - **旧格式一次迁移**：旧数组根日志，或日志缺失时，仅从 `library/asset-delete-archive.json` 读取旧累计值（`{"retainedCleanupCount":N,"trashBytes":B}`），在首次完整日志写入时与 `entries` 一并迁移；空事务列表且有旧旁路来源的恢复也可完成迁移。日志与旧旁路均缺失的健康库没有历史状态需要迁移，正常读取不要求写入空日志。对象根日志落盘后，恢复和所有写入口不再读取或写入旧旁路文件；旧文件保留，仅作为迁移前来源，陈旧值、异型文件或目录占位均不能复活已归零的统计。迁移失败按原子写所处阶段保留完整旧或新快照，下次恢复重试，不重复导入旧累计值。旧版本只接受数组根，读取新对象时进入删除日志只读告警态；降级使用前须保留数据并恢复与旧版本匹配的完整备份，不支持自动反向迁移。

不得继续作为可用资产暴露——恢复/列表流程在规范化索引与内存投影中把该条目标为冲突不可用并随列表返回警告；标记期间媒体协议处理器与任何按 relPath 的打开拒绝为该 assetId 服务（原 relPath 可能已绑定后来文件，解析它会把占用者的替换文件当作原资产展示），也不得以该条目为源复制入项目或收藏；标记只随日志事务解决而解除——原名重新 no-replace 绑定预期身份、索引耐久提交去项或日志按恢复规则清除，不得靠重新列表静默消失。③ 隔离身份一致且耐久后才原子提交不含该条目的 `library.json` 并 fsync `library/`；提交失败时索引仍含该资产，恢复流程按日志把同一身份 no-replace 移回原位。④ 索引提交成功后，只能用绑定步骤①已打开身份的操作系统删除原语清理隔离项并 fsync `.trash/`；普通 `unlinkat(隔离名)`、再次 stat 后按名称 unlink 或任何 check-then-use 退化均禁止。平台没有身份绑定删除能力、删除/fsync 失败或进程中断时，保留隔离项并返回/记录 `cleanupPending`，索引不得回滚；其中「索引已提交 + 隔离项身份核验一致 + 平台无原语」的终态条目在下次恢复按权威视图判定后折叠退役（见上文「已完成清理项的折叠归档」，issue #359）。启动及每次库列表/写入前先恢复日志：每条事务先重读规范化索引并按已打开身份复核其他活动条目；若其他条目已引用预期身份，不得移动或删除其当前目录项，隔离项存在时只按身份绑定能力清理该额外目录项、能力不足则保留 `cleanupPending`，隔离项不存在时可清除日志。没有其他活动引用且索引仍含 assetId 时：若隔离项尚未生成且原路径仍绑定预期身份，清除这条未开始事务；若隔离项身份一致，则只在原目标名空缺时 no-replace 回迁；其余缺失、身份不符或路径占用均保留日志、按上述冲突期隔离规则将条目标为冲突不可用并警告。索引已无 assetId transaction id、路径越出固定原资产位置或 `.trash/` 随机名单项时整份恢复进入只读告警态，所有库写入/删除暂停，不猜测路径、不移动或删除任何文件。事务完成且相关目录已 fsync 后才原子移除日志项；所有日志写入均保留同一根对象中的累计统计，折叠退役与统计增量同次提交（#421）；`.trash/` 永不参与 AssetRef - **分工**：`kind` 回答"是什么"，`view` 回答"哪个角度"，`groupId` 把同一主体的三视图绑成一组；`tags` 只用于前两者覆盖不了的自由维度（如「赛博朋克」「雨夜」）。能用结构化字段表达的不写成标签，避免同义标签发散。

- **迁移身份稳定性**：检测到迁移/修复即耐久回写，保证重发 id 跨读取稳定。只读告警态、迁移挂起态或损坏索引的局部视图不暴露未落定的新身份；不能在每次列表时再次产生漂移 id。
- **绑定方式**：分类信息写在 `library.json` 索引项里、以资产 id 为键；改标签、换组、改视角只更新索引，不动媒体文件。
- **快速读取**：`library.json` 启动时全量载入内存（桌面量级，数千条索引项仅数百 KB），列表页筛选/搜索全走内存过滤，媒体文件懒加载。规模失控时再迁 SQLite（见十三）。Swift 原生侧目前每次库操作重读并逐条规范化索引（而非仅启动时载入）：时间戳规范化成本已由 [issue #824](https://github.com/hailingu/PlotWeave/issues/824) 消除（严格快路径 + 共享缓存格式器，复测 ≈ 63 µs/资产、1600 资产列表中位 ≈ 100 ms），每次操作重读整份索引的设计层边界与完整规模-耗时基线见[持久化 §10.2](persistence.md#102-写入安全)（[issue #730](https://github.com/hailingu/PlotWeave/issues/730)）。

#### 库导入的20 MiB物化边界（issue #682）

库资产仍须非空且不超过 `20 * 1024 * 1024` 字节，等于上限允许；超限保持 `文件超过 20 MiB 上限` 文案。共享Web门面在读取 `File.arrayBuffer()` 前检查 `file.size`，读取后再按实际缓冲长度检查，随后才展开 `bytes: number[]`；Swift与Tauri的Web入口使用同一预检，浏览器预览的内存回退不变。

Tauri的导入参数借用框架已解析的 `InvokeBody::Json` 先取数组长度：界内委托原有 `Vec<u8>` 参数解码；越界只逐项运行同一 `u8` 反序列化规则，不分配字节向量，以保留首个非法字节的原参数错误（包括位于上限之后的非法项）。越界且全为合法字节时，才以原 `LibraryError::Limit` 到命令出口。缺参、Raw载荷、异型仍委托原参数解码器。既有存储内核仍复验大小，索引净化、删除日志恢复及资产身份／路径约束不变。Swift已有数组长度先于 `Data` 构造的检查，原生文件面板不经JS数组。

这里防止的是受信文件路径上的无界读取与后续JS数组／Rust字节向量放大；Tauri框架接收并解析JSON发生在参数预检之前，本层不声称提供HTTP请求体上限或阻止恶意调用者先提交大JSON。未用实机大文件内存峰值或未核实的IPC默认上限充当验收证据。Rust回归以小注入预算验证等号和越界，保证超限时根本不调用会分配向量的解码器。

### 7.3 流转规则

- **库资产进入项目 = 拷贝**：把库素材放上画布或设为角色头像时，文件拷入项目 `assets/` 并生成项目级 AssetRef（新 id）。项目不持有对库文件的引用，因此库侧可随时清理而不产生项目内的悬空引用。
- **AI 生成结果必须落盘后再引用（文生图已实现）**：厂商临时 URL 不得出现在文档里——临时链接会过期，直接引用会导致画布内容日后无法打开。生成结果默认落项目资产；「收藏到资产库」及 `collect_library_asset` 仍待实现，#29 关闭不包含该链路。
  - **Swift 原生下载边界（[PR #526](https://github.com/hailingu/PlotWeave/pull/526)）**：只接受无内嵌凭据的 HTTPS URL；初始请求及每次重定向都校验全部 DNS 结果，再连接到获准的固定 IP，原 URL 主机保持为 HTTP／TLS 身份。非全球 IPv4（含基准测试、保留、文档、协议用途地址）及其兼容、映射、NAT64、6to4／ISATAP 表示不能放行；普通 IPv6（[issue #528](https://github.com/hailingu/PlotWeave/issues/528) 修复）按 [IANA 全球单播分配登记](https://www.iana.org/assignments/ipv6-unicast-address-assignments)的 ALLOCATED 前缀白名单分类（`globalV6Rows`），并保留特殊用途登记列出的全球可达 `2001::/23` 例外（anycast／AMT／AS112／ORCHIDv2／无人机远程 ID）；`2001:db8::/32` 文档段自 APNIC `2001:0c00::/23` 行内扣除。Teredo、局部 NAT64、基准测试、废弃 ORCHID 及文档／局部／空间外范围拒绝；登记未列出的名义 `2000::/3` 空间（含 `2d00::/8`、`2e00::/7`、`3ffe::/16` 与 `2001::/16` 内未分配间隙）按登记说明视为保留并拒绝。混合公网／非公网答案整体返回 `PW_NETWORK_REFUSED`，不连接到其中的公网答案。全部地址获准后，只有 `PW_DOWNLOAD_NETWORK` 连接失败才按顺序尝试后续地址，所有候选共享同一 120 秒 hop 截止时间和剩余图像作业预算；取消、预算耗尽、策略／framing 拒绝或 HTTP 错误不推进候选。既有 5 跳、32 MiB、绝对截止时间及取消检查保持；注入传输回归不代替真实公网 TLS 验收，见[修复矩阵 R1–R3／R18–R19](../swiftui-react-flow-pr526-fixes.md)。
  - **IPv6 保留／未分配分类修复（[issue #528](https://github.com/hailingu/PlotWeave/issues/528)、[PR #526 R40](../swiftui-react-flow-pr526-fixes.md#ipv6-保留与未分配范围的后续修复r40)，已实现）**：`publicV6` 原先以名义 `2000::/3` 黑名单兜底，放行了登记标为 RESERVED／未列出的地址（`3ffe::1`、`3000::1`、`3fff:1000::1` 独立编译真实谓词复现为 true，不代表真实内网访问已复现）；修复后同一验证输出 false，`2606:4700::1111`／`fd00::1` 对照不变。既有“全球地址邻接”测试中 `3fff:1000::1` 允许案例随修复移除；新增回归覆盖保留行、`2001::/16` 未分配间隙、各分配前缀首尾边界（`2410::/12`、`2610／2620::/23`、`2630::/12`、`2a10::/12` 为独立登记行，不被相邻 /12 覆盖），以及 literal／全保留 DNS／混合答案／重定向到保留目标先拒绝且传输零连接（`NativeNetworkPolicyTests`／`NativePublicDownloadTests`）；获准候选回退、原 hostname TLS 身份、共享 deadline、取消与大小上限既有语义保持。静态表与登记核对日期 2026-10-13（登记页更新日期 2025-10-10）：IANA 未来新增分配需人工同步 `globalV6Rows` 并同批更新边界回归，无运行时同步机制。真实特殊网络路由、真实公网 TLS 与计费模型保留既有缺口，未验证。
- **浏览器预览拷贝语义（#8）**：导入时基于源 blob 创建独立 object URL，绑定项目资产 id；删除源库条目不影响已导入缩略图。此映射仅在会话内有效，浏览器重载后丢失；预览回退不提供桌面端的文件持久化。
- **延迟回收**：删除引用资产的节点/设定时不立即删文件，由后续「清理未引用资产」命令统一回收（首版可只做手动触发）。
- **项目复制 = 文档级复制**：复制件的 `project.id` 必须替换为目标项目的新 id（持久化层强制 id = 目标路径 id，禁止沿用源 id），创建时间取复制时刻；资产索引随文档原样带走（与 `avatarAssetId` 等
  引用字段保持一致解析，§8.1）。当前桌面实现先创建副本，再经 Rust `copy_project_assets` 将媒体拷入副本 `assets/`，最后保存文档；失败时清理副本并报告错误，清理也失败则报告残留副本。整个流程是分步操作，不宣称跨文件原子事务。**媒体拷贝的持久性屏障**（[issue #259](https://github.com/hailingu/PlotWeave/issues/259)，已实现）：`copy_project_assets` 在成功返回前对每个副本文件内容 fsync、对接收条目的每个目标目录（含新建层级在宿主中的条目）fsync——与库资产导入的原子写同级持久，先于副本文档保存引用；任一同步失败原样上浮并回滚目标资产树，不提前报告成功（非 Unix 平台目录句柄无法 fsync，沿用 §10.2 `create_dir_all_durable` 的平台现状）。**复制命名策略保证不超上限**：新名 = `{源名} 副本`（已存在
  则 ` 副本 2`、` 副本 3`…），拼接结果按字符数超过 64（§9.3 项目名校验口径）时先
  截断源名至可容纳后缀再拼接——直接追加后缀会让接近上限的合法源名复制即被
  持久化层拒绝，复制操作必须总能成功。

### 媒体响应的文档隔离（#654）

`pwmedia` 的响应层保留规范的图片／音频／视频类型，其他声明仅以 `application/octet-stream` 交付原字节；磁盘 `AssetRef.mime` 和共享词法规则不变。SVG 继续以图片类型交付，媒体响应统一附带强制 sandbox／禁脚本 CSP 与 nosniff；404 保持固定纯文本。读取授权、描述符身份、容量和取消仍由原 owner 负责。真实 WK 正向对照、SVG 文档／图片回归及限制见[媒体响应边界](../development/media-response-boundary.md)。

### 原生投递粒度（#718）

Swift `NativeMediaScheme` 的 WKURLSchemeTask 回调受 WebKit 框架约束只能在主线程执行（[WKURLSchemeTask](https://developer.apple.com/documentation/webkit/wkurlschemetask) 协议方法由主线程调用），因此大媒体的响应性由**投递粒度**决定，而非后台读取：投递循环以 **4 MiB**（`NativeMediaScheme.deliveryChunkBytes`）为一个「后台 pread + 主线程 `didReceive`」单元——256 MiB 项目媒体上限只产生 64 次主线程投递（64 KiB 粒度需 4096 次，issue #718 修复前），单次投递为亚毫秒级数据搬运，主线程在加载期间保持可响应；后台读取、取消传播、身份绑定与并发闸门契约不变，瞬时读取缓冲峰值由闸门约束为 ≤ 4 并发 × 4 MiB。Tauri 侧 `pwmedia` 处理器在阻塞线程整包缓冲读取、经异步 Responder 单次 respond 交付（协议 API 无流式 body，见 [media_protocol](../../../src-tauri/src/media_protocol.rs)），主线程不参与媒体字节搬运，无对应问题。

### 未绑定库导入副本的隔离（issue #864）

Web 拖放与原生库绑定均在导入返回后复核权威 MIME、目标节点类型及会话所有权；失败时调用 `discard_project_asset_import(id, assetId)`，前端导入后的预检失败也走同一路径。成功绑定及其撤销/重做保留原有媒体生命周期，不随撤销删除字节。 [issue #886](https://github.com/hailingu/PlotWeave/issues/886) 的保留边界明确如下：导入已绑定后，即使在首次接受保存前撤销，后续空引用保存也保留媒体与会话凭据，以支持 redo；保存曾接受过该资产后，回收资格永久退役。退出后未引用的最终名媒体仍在，内存凭据不跨重启恢复，不自动猜测孤儿并删除。清理入口是完全退出、备份项目，再根据文档全部资产引用及媒体清单人工核对未引用文件；保留副本优先于误删 redo／用户媒体，当前没有自动孤儿扫描或空间回收承诺。

Swift 项目 actor / Rust 项目操作锁只接受本宿主为本次库拷贝登记的身份凭据，不接受客户端 `relPath`，不操作源库。已保存文档接受过的资产永久退役该回收资格；正在被文档以 id/路径引用、身份改变或无凭据的文件均拒绝隔离。未绑定副本放入项目 `assets/.trash/import-…/`，保留 `receipt.json`（逻辑身份、原路径、设备/inode）与 `media` 原字节；先持久化凭据，再隔离并按目标→源目录顺序同步。活动资产准入继续拒绝 `.trash`。

隔离是可回收记录，不代表物理删除或空间已释放。清理失败保留现场和凭据并向调用方显式报错；自动崩溃恢复扫描及物理释放尚未实现。人工处理前完全退出应用、备份项目并逐项核对隔离凭据；此目录不得作为活动资产索引使用。浏览器预览只移除独立内存映射，不声称磁盘回收。

项目导入的同步凭据失败（[issue #890](https://github.com/hailingu/PlotWeave/issues/890)）：媒体落位后凭据登记抛错时，在同一 actor 无挂起事务内移除刚写入的最终名，并同步目录后返回原始错误；pendingMedia 只在凭据成功后发布。回滚本身失败返回 `PW_IMPORT_ROLLBACK_FAILED`，包含登记与清理诊断并保留现场，不能将失败宣称为媒体已删除；正常导入、既有凭据隔离和撤销保留语义保持。
