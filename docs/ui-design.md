# PlotWeave UI 设计规格

> 状态：草案 v1（整体待评审），含已实现与规划内容；2026-09-09 按已关闭 issue 核对，逐项依据见[设计同步记录](design-sync.md)。未标记完成的规划不因本次同步而视为已实现。
> 适用范围：应用外壳、画布编辑器、设定集与资产库面板、AI 对话、设置页、设计令牌与动效规范、macOS 原生质感实现路径（§12，规划中）。
> 设计基准：Apple Human Interface Guidelines（HIG），macOS 优先；Windows 通过设计令牌分层预留适配。
> 配套文档：《数据模型设计》（docs/data-model.md）。本文档引用的 §x.y 章节号均指向该文档。

## 一、设计目标与原则

PlotWeave 是画布式短剧创作工具。UI 设计从 HIG 推出五条硬约束，后续每节决策都能回溯：

1. **跟随系统外观，浅深双外观齐备**。HIG 深色模式章明确「避免提供 App 特定的外观设置」「确保 App 在两种外观模式下都能很好地呈现」。应用内不设主题开关。
2. **语义色令牌，不硬编码颜色**。每个颜色令牌有浅色/深色/增强对比度变体；文本与背景对比度 ≥ 4.5:1。
3. **品牌色只进内容层**。材质与窗口 chrome 保持单色；青→品红品牌渐变只用于节点选中态、branch 连线、关键操作按钮与 AI 标识（HIG 颜色章：「考虑在内容层中使用颜色体现品牌形象」）。
4. **形态即语义，不以色别物**。节点类型靠图标与结构形态区分（HIG 包容性：避免仅靠颜色传达信息）；颜色只表达状态（选中/悬停/失效/AI 改动）。
5. **动效即物理**。一切手势驱动的动画可中断、从当前值起步、继承速度；默认临界阻尼弹簧，仅动量交互允许回弹。

跨平台策略：**设计令牌三层结构**（原始色板 → 语义令牌 → 组件令牌）。首版只交付 macOS 外观；Windows 适配 = 替换原始层与材质实现（亚克力/Mica）、字体栈接 Segoe UI，不动组件结构。

## 二、设计令牌体系

### 2.1 三层结构

```
原始层（palette）     语义层（semantic）        组件层（component）
cyan-500 #21D4FD  →  accent.alt            →  node.selected.border
magenta-500 #FF2E88  accent                →  edge.branch.stroke
gray-900 #131316  →  surface.canvas        →  canvas.background
                     material.sidebar      →  sidebar.background
                     text.primary/secondary →  任意文本
```

组件只引用语义令牌。浅色/深色/增强对比度是同一令牌的不同取值；`prefers-reduced-transparency` 时材质令牌退化为不透明实色。

「组件只引用语义令牌」由机器契约验证并推广到 src 下全部组件样式表（issue #278，`src/styles/sheetTokens.test.ts` 负责真实样式表契约，`sheetTokensSemantics.test.ts` 负责语义夹具，两者共用 `sheetTokensEngine.ts`，不复制取值实现）：按 glob 发现样式表（新增样式表自动进入契约，不维护文件清单，也不要求每张表包含展示色声明；仅布局、动画或空样式表同样进入扫描）、展示色声明（含 SVG `fill`/`stroke`、`background-color`/`background-image` 长形、`text-shadow`、`border` 全部简写/长形与 `border-image`(-source)；标准属性名按 ASCII 大小写不敏感先归一再分类，自定义属性名保持大小写敏感）不得字面硬编码 hex/大小写不敏感的函数色/CSS 具名色（`transparent` 不计；经展示色属性传递消费的局部自定义属性同样受禁；用户内容色/遮罩/声明自洽状态对为具名例外，豁免绑定到已审计的字面值与条数）、引用的 `var()` 在全部支持环境（外观 × 对比度 × 透明度 × 动效）按值链传递可解析且类型相容——令牌或局部变量自身引用缺失名、值为保证无效形态（`initial`，及全局作用域上退化为 `initial` 的 `unset`）、仅在部分环境成立而引用无条件、逗号选择器任一分支无可达定义、同选择器同条件后位定义（层叠源序后写）或可达局部同名定义（遮蔽根令牌）为保证无效值，或解析值按已建模的属性文法不相容（把尺寸/裸数值令牌用进 `color`，或不支持图像的属性引用渐变/URL），均判违例。在已支持的简单后代/子代选择器链中，先定位最近定义元素：元素自身的指定值先于祖先继承值，近祖先先于远祖先，祖先的 `!important` 不能越过继承层级覆盖自身值；同元素候选再比较重要性与源序，逗号分支及媒体环境独立选取，最近值失效时走消费点 fallback 而不回头使用远祖先同名值。同选择器同条件内多条局部自定义属性同名时，胜出定义先按重要性（`!important` 优先于普通声明）再按真实源序选取最后一条，且同名分组在输出中的位置跟随其最后一次出现的真实源序，不因 Map 键首次插入位置而误判基线定义早于后续异条件定义；该重要性优先规则跨活跃条件分组仍然成立——媒体块内的 `!important` 定义不因其条件在无条件后位普通定义之前而被覆盖。根令牌源 `tokens.css` 的 `:root` 同名自定义属性也先过滤活跃媒体环境，再按重要性与源序取胜；重要根值为保证无效值或断链时，消费点仍进入既有 fallback 规则。根令牌入口仅建模 media 包住根规则的条件布局；反向在根规则内部嵌套 at-rule（包括 media）的声明布局尚未建模，会明确拒绝；在 `@supports`/`@layer`/`@container` 等未知 at-rule 内的根自定义属性，包括非活跃 media 中的嵌套入口，显式报 `TOKEN_ROOT_AT_RULE_UNMODELED`，不返回跳过这些声明的旧值；其他 at-rule 不含根令牌时不触发此限制。类型校验逐逗号选择器分支解析可达且活跃的局部定义：`background`/`background-image`/`border-image`(-source) 接受图像，SVG `fill`/`stroke` 额外接受 URL 绘制引用，边框、轮廓、文字阴影等属性拒绝图像；主变量缺失、保证无效或值链断裂/循环时递归解析 fallback，实际生效的回退值仍须通过类型校验，空回退不能独立成为展示色声明。接线扫描与类型扫描共用作用域和主值/fallback 取值规则：主值可用时不诊断未选中 fallback 中的悬空名；主值失效后递归校验实际选中的回退路径，变量环判定仍包含 fallback 依赖（接线豁免绑定承载属性与出现条数）。纯颜色消费点校验完整顶层值，颜色前后夹带尺寸、裸数值或额外词形会被拒绝；合法边框颜色列表及含尺寸的边框/阴影简写继续通过。纯值检查集中于 `src/styles/cssColorContract.ts`。这是一组静态契约检查，并非完整 CSS 文法与层叠引擎；跨选择器特异性、复杂选择器、颜色函数内部参数及完整简写文法仍未建模（[PR #288 审查处理记录](reviews/pr-288-review-5279748560.md)）。危险动作黄金接线要求目标规则唯一且无条件（媒体块内同名规则会使生效值随环境分叉；唯一性按选择器列表逐分支判定，后续规则若在逗号分支中含目标选择器也计入覆盖），生效值取规则内该属性（属性名先按标准大小写归一）按重要性（`!important` 优先于普通声明）再取源序最后一条、令牌配对按 浅/深 × 基线/more × 基线/降透明度 全组合断言（一级文本全程 ≥ 4.5:1，次级文本 more 下升档 ≥ 4.5:1，含 reduce-transparency 实色材质，§2.6）。例外为逐项注册表且双向校验——新违例进不来，已修复或属性/条数变动的表项必须更新。分表契约（nodes/panels/home 菜单钮）继续作为各域回归防线并存。

### 2.4 字体

- 栈：`-apple-system` / `PingFang SC` / `"Segoe UI"`（Windows 段预留）/ `sans-serif`。
- 阶梯：说明 11 · 辅助 12 · 正文 13（macOS 基准）· 区块标题 17 semibold · 大标题 24 bold。
- 字距随字号：大字负字距（24pt 约 `-0.02em`），正文近 0，小字微正。行高随字号反向变化。
- 间距单位用 rem，尊重用户文本大小设置。

### 2.5 形状、间距、动效

- 圆角：`radius.sm 4`（标签/小按钮）· `radius.md 8`（按钮/输入框）· `radius.lg 12`（节点卡片）· `radius.xl 14`（弹层/表单）。
- 间距：4pt 网格（`space.1=4 … space.6=24`）；面板内边距 12–16，组件间 8。
- 动效令牌：
  - 默认弹簧 `damping 1.0 / response 0.3–0.4s`（无回弹）；
  - 动量交互（甩动、选中场景等伴随用户动作动量的场景）`damping ~0.8`；
  - 手势结束后动画以松手速度为初速度继续（速度交接）；
  - `prefers-reduced-motion` 时全部降级为 200ms 透明度交叉淡化。

### 2.6 无障碍变体

每个令牌与组件必须回答三个问题：`prefers-reduced-motion`（弹簧/滑动 → 交叉淡化）、`prefers-reduced-transparency`（材质 → 实色去模糊）、`prefers-contrast: more`（背景近实色 + 明确描边，文本对比度升一档）。

## 三、应用外壳与导航

### 3.1 结构：文档式双界面

**慢速持久化时的响应性（[issue #138](https://github.com/hailingu/PlotWeave/issues/138)，已实现）**：
项目／会话保存、资产库操作、设置落盘及媒体 URL 校验的同步工作在后端阻塞
线程池执行，文件锁等待不占用原生主线程。既有保存中、失败重试与退出冲刷
反馈继续以实际命令完成为准；排队不等于保存成功。原生心跳及慢保存期间媒体
读取的验证见[状态矩阵与测量](development/invoke-responsiveness.md)；未测量画布帧率。

- **项目首页**（文档浏览器）与**编辑器**是同一窗口的两种状态；同一时刻只打开一个项目（单写者模型，数据模型原则 5），打开另一项目 = 当前窗口切换内容，切换前调用 `flushPersist()`（§10.2）。
- **返回首页与保存落定的摘要时序（issue #101）**：返回首页不等待保存链——列表立即读取，先展示当前磁盘现状；编辑器卸载冲刷/在途保存落定成功（含保存失败登记后的链上后台重试成功）时，存储层通知首页自动再刷新一次，卡片随之显示最新名称/统计/更新时间。保存尚未落定或失败期间不虚报成功，首页始终反映磁盘真实内容；无修改离开不触发保存、不盖新戳。并发刷新按发起序收敛，较旧的列表响应不覆盖较新的结果；编辑器打开期间保存落定不触发列表刷新（首页不可见，且列表 state 更新会整树重渲染编辑器子树）。
- **退出冲刷屏障（issue #119，已实现）**：正常关闭窗口、macOS ⌘Q 与 Dock「退出」共用一道应用级屏障，覆盖三类未落盘数据——画布防抖脏文档（编辑器经注册表向屏障暴露立即冲刷闸）、项目保存链的失败重试登记与 AI 会话主文件。屏障先冲刷到固定点（冲刷期间的新编辑继续等待）再放行退出；仍有失败则保留窗口并在窗口顶部显示「已阻止退出」诊断横幅，点名失败的画布保存与 AI 会话数量，可再次尝试退出；防抖保存失败的自动重试节律保持运行。
- **按需加载（#34，已实现）**：首页随入口加载，编辑器和设置页通过 `React.lazy` 分域加载，React Flow 运行时依赖封闭在编辑器域。打开项目、打开设置以及设置关闭返回时，经 `startTransition` 保留当前界面直到目标就绪，避免惰性 chunk 未就绪造成整窗空白；不额外引入 `manualChunks`。
- **设置页往返的重挂载种子（#61/#118，已实现）**：设置页与项目界面是互斥路由，往返会卸载并重挂载编辑器。重挂载时画布文档与 AI 会话一样从保存路径维护的带外最新引用按项目 id 解析挂载种子，而非打开项目时刻的快照——防抖未落定、在途与保存失败三种时序下，内存最新内容都不被旧快照回退（设置往返前的编辑与保存不因往返丢失，下一次全量保存不产生版本回滚；在途保存未落定时卸载由防抖落盘立即补交最新文档，不依赖在途落定）。种子解析后项目名以编辑器改名通道为准，改名同步补丁带外引用。带外引用不跨导航存活：打开尝试开始时清除（返回首页触发的卸载冲刷可能经保存路径复活引用，打开尝试才是权威失效点），重开项目一律以磁盘载入为准（首页改名或外部编辑可能已更新盘上文档）。
- 窗口最小尺寸 960×600；尺寸/位置记忆于会话级，不进 ProjectDocument。

### 3.2 项目首页：竖版海报片库

短剧是竖屏内容，项目卡片即「一部剧的海报」：

- 卡片固定 180–220pt 宽，**9:16 竖版海报**：封面 + 底部渐变压字排版剧名 / 统计信息（场次数、结局数——均可从画布节点计数派生）+ 相对更新时间。分集信息的数据源已定稿（文档级 `episodeTitles` + 节点 `meta.episodeNo`，数据模型 §3/§4.1）；卡片上的分集展示属 UI 迭代项，不再以数据模型为前置依赖。
- **封面来源**：用户从项目资产中选定；未选定时用剧情结构的「织线」mini-map 兜底（发光节点与分叉线的抽象图，呼应 PlotWeave 之名）。
- 窗口变宽时网格增加列数，卡片不拉伸。
- 工具栏：搜索框（内存过滤 `index.json`）+ 「＋ 新建项目」；空状态居中引导「创建你的第一部短剧」。
- 右键/悬停菜单：打开、重命名、复制、删除。删除走确认对话框（HIG：仅真正不可逆操作使用确认）。
- **悬停 ⋯ 菜单钮配对令牌**（[issue #261](https://github.com/hailingu/PlotWeave/issues/261)，已实现）：浮于海报之上的窗口层控件——前景 `text.primary`、背景/描边经 `poster.menu.*` 配对令牌随外观切换（修复前背景恒白而前景随外观，暗色下 hover 浅字白底仅 1.12:1 不可辨认）；hover 换实色 hover 面，`:focus-visible` 保留键盘入口（与右键菜单同源）。常态半透明面在任意明暗海报内容上按纯黑/纯白最劣合成 ≥ 4.5:1，`more` 近实色 + 描边加强、`reduce-transparency` 退化实色（§2.6 三变体，机器契约 `homeTokens.test.ts`）。
- **打开失败反馈**（[issue #98](https://github.com/hailingu/PlotWeave/issues/98)，已实现）：打开项目被持久层拒绝（文档版本过新、文件损坏/不可读、I/O 失败）时，停留在首页并在工具栏下方显示非阻塞警示横幅（`role=alert`），点名失败项目并给出可读原因——版本过新的消息自带「请升级应用」指引；首页操作能力保留，失败路径不触发任何回写。横幅停留至下一次打开尝试开始（每次新尝试即视为旧错误过时）或新建项目成功，不把旧错误带到其他项目；失败项目不在当前列表时（如列表读取后已被删除），横幅用通用「打开项目失败」文案。
- **列表读取失败反馈**（[issue #133](https://github.com/hailingu/PlotWeave/issues/133)，已实现）：读取失败 ≠ 空列表——`projects/` 目录级故障（权限变更/磁盘卸载/目录被替换为符号链接/杀毒锁目录；单个坏文件由列表以损坏占位卡呈现（见下条），不在此列）导致整次列举失败时：启动即失败（无已知列表）以**错误态**代替首次使用引导（诊断 + 重试，注明已有项目未受影响），工具栏「＋ 新建项目」保留可用；返回首页触发的**刷新失败**保留已显示的卡片（最近一次成功读取），横幅注明刷新失败并提供重试；较旧的失败响应不覆盖较新的成功（代际收敛）。项目文件本身不受影响，重试即重新拉取列表。
- **损坏占位卡**（[issue #123](https://github.com/hailingu/PlotWeave/issues/123)，已实现）：项目文件存在但不可读或不可解析（JSON 损坏、信封不可判型、非并发删除的 I/O 读取失败）时，列表以占位卡呈现而非静默跳过——坏项目可见可定位。深底虚线框降低视觉权重；占位名「无法读取的项目（<受信 id>）」携带受信路径 id（PR #196 评审：id 即 `projects/` 下坏文件名主干，多个坏项目占位名因此互不相同，删除确认对话框与打开失败横幅均能点名唯一目标，避免删错坏文件）；诊断文案替代统计行，无封面与相对更新时间。点击仍走打开入口，完整诊断由打开失败横幅（issue #98）呈现；卡片菜单保留（删除可清理坏文件）。信任链拒绝（符号链接/异型条目）与读取时已并发删除的条目不产生占位卡（数据模型 §10.2）。
- **项目变更失败反馈**（[issue #132](https://github.com/hailingu/PlotWeave/issues/132)，已实现）：创建/重命名/复制/删除的存储拒绝（如目录只读、磁盘满）不再只写控制台日志——工具栏下方显示非阻塞警示横幅（`role=alert`），点名动作与目标（删除/复制经当前列表解析项目名，创建/重命名点名尝试写入的名称；解析不到时回退 id）并给出可读诊断；横幅内提供**重试**按钮（同参重发失败的动作），首页操作能力保留。新一次变更尝试即视为旧错误过时（横幅清除），结果按尝试序提交——并发动作后发起者拥有终态，旧尝试的迟到失败不覆盖；动作成功不虚报失败（创建成功但随后打开失败由打开失败横幅 issue #98 承接，不属变更失败）。重命名走拒绝式保存：落盘失败即时呈横幅，同时经保存链登记后台重试。后台定时重试或退出冲刷将本次文档真正落盘后，自动清除对应横幅和重试按钮；恢复通知按提交给保存边界的文档对象与尝试序匹配，旧请求或其他文档（即使同名）的成功不得清除当前错误，同一尝试成功恢复后迟到的拒绝不得复活横幅。创建/复制共用完整尝试队列（[PR #199 评审修复](https://github.com/hailingu/PlotWeave/pull/199#pullrequestreview-5238496725)）：每次从存储读取最新基线，再执行变更，拒绝后重列核对新增的非固定示例项目；这三段全部结束，下一次创建或复制才开始读取基线。因而两次请求都拒绝时也不会互相认领产出，且不依赖 React 列表镜像何时重渲染。基线读取失败时不执行变更，横幅提供重试。创建拒绝但对账发现新增的非固定示例项目时保留其卡片，不提供重试；复制发现新增的非固定示例项目则视为可能部分提交，横幅给出诊断与手动处理提示，无重试。只有成功重列并确认没有新增的非固定示例项目（包含复制清理成功）才提供同参重试。对账读取也失败时保留已知卡片与列表诊断，变更横幅明确提示「无法确认是否已创建，请刷新项目列表后核对」，不给盲重试；后续新操作仍须重新读取存储基线。

#### 首页项目变更重试安全矩阵（PR #199，已实现）

归属与重试安全由 `useCreateFamilyAttempts` 负责，首页创建、复制及其横幅重试入口均经过同一队列；`useProjectSummaries` 负责列表读取成功/失败和展示状态，`useHomeActionFeedback` 负责按用户发起顺序发布终态。以完整串行尝试替代失败后按候选项目抢占归属，不改变 IPC 或落盘格式。

| 前置/状态 | 动作与事件顺序 | 可观察结果 | 跨迁移不变量 | 验证结果 |
| --- | --- | --- | --- | --- |
| 两个创建/复制请求均拒绝，仅后者提交 | 同时发起；前者对账结束后，后者才读取新基线并执行 | 后者无盲重试；复制保留部分提交提示 | 一个尝试的产出不能被另一尝试认领 | `App.test.tsx` 并发失败用例通过；`useCreateFamilyAttempts.tauri.test.tsx` 四种入口组合通过 |
| 前者提交，后者无写入 | 前者完整结束 → 后者读取基线 → 拒绝 | 后者呈错误并可重试 | 基线从存储读取，不依赖 React 渲染更新 | App 既有并发用例与 Tauri IPC 前次提交/后次无写入用例通过 |
| 创建/复制已提交，但失败对账读取也拒绝 | 写入 → 拒绝 → 列表读取拒绝 | 原始诊断与无法确认提示可见，无重试；已知卡片保留 | 未知结果不能降格为未提交或成功 | App 创建/复制未知结果用例与 Tauri IPC 对账失败恢复用例通过 |

| 复制失败且清理成功 / 源读取失败 | 拒绝 → 重列无新增非示例项目 | 可同参重试，成功后清横幅 | 重试只用于确认未提交的尝试 | App 同参重试用例与 Tauri IPC 源读取失败、清理成功用例通过 |
| 复制部分提交 / 清理也失败 | 拒绝 → 重列存在新增非示例项目 | 保留诊断与手动处理提示，无重试 | 不通过重试再次生成副本 | App 既有部分提交用例与 Tauri IPC 清理失败用例通过 |
| 对账失败后再发起一次请求 | 前次释放队列 → 新请求读取最新基线 | 队列继续推进，旧项目不被当作新产出 | 失败不阻塞队列，旧失败不覆盖最新状态 | Tauri IPC 失败后恢复用例与 App 既有序号用例通过 |
| 创建/复制在途时最后一个项目被删除，本次变更无写入 | 基线含旧项目 → 删除完成 → 创建拒绝 → 对账列表自动播种 | 保留示例卡片，原始失败仍可重试 | 固定示例身份不属于创建族产出，列表维护不能掩盖动作失败 | Tauri IPC 创建/复制在途删除回归通过；恢复后同参重试通过 |
| 并发删除后的普通刷新先完成播种 | 基线含旧项目 → 删除与普通刷新 → 创建拒绝 → 对账 | 与对账自身触发播种时相同 | 归属判断不依赖哪次列表读取触发维护写 | Tauri IPC 创建/复制与普通刷新交错回归通过 |
| 播种后本次变更也提交了普通项目，但返回拒绝 | 删除与播种 → 新项目落盘 → 拒绝 → 对账 | 仍识别为已提交，不开放盲重试 | 只排除精确的固定示例 id，不按名称或 `sample-` 前缀忽略产出 | Tauri IPC 同名普通项目、同前缀非示例身份回归通过 |

| 重命名保存失败，登记文档稍后自动或退出冲刷重存成功 | 原始失败横幅 → 同一文档的重试落盘通知 | 横幅及重试按钮清除，卡片刷新为新名 | 只有当前尝试所提交文档的真实恢复可清除其错误 | `App.test.tsx` 回归通过；`useHomeActionFeedback.tauri.test.tsx` 定时重试/退出冲刷集成通过 |
| 当前重命名仍未保存；收到其他文档（包括同名文档）落盘通知 | 无关通知 → 当前文档最终恢复 | 无关通知不清错，匹配通知清错 | 以文档对象和尝试序绑定恢复，不以项目 id/名称猜测 | App 同名不同身份回归与真实保存链持续失败/恢复集成通过 |
| 已开始新的重命名或其他变更，旧读取/恢复迟到 | 新错误出现 → 旧尝试注册或恢复 → 新尝试恢复 | 旧尝试不接管恢复登记、不清掉新错误 | 最新用户尝试拥有反馈终态 | App 旧读取迟到、连续重命名及跨动作恢复回归通过 |
| 成功恢复通知先于原保存拒绝的处理 | 同文档成功通知 → 迟到的失败处理 | 已解决横幅不复活 | 同一尝试的成功恢复对迟到失败保持终态 | App 成功通知先于拒绝处理回归通过 |

列表播种归属（[PR #199 评审修复](https://github.com/hailingu/PlotWeave/pull/199#pullrequestreview-5239171531)）：删除不经过创建族队列，最后一个项目删除后，普通刷新或失败对账的 `tauriList` 都可能写入固定示例。`useCreateFamilyAttempts` 从既有 `seedProjects` 定义取得精确 id 集合，在判断新增产出时排除这些身份；Tauri 创建生成 `p-` 身份、浏览器回退生成 `local-` 身份，复制也经过创建入口，均不会生成固定示例 id。只排除固定身份，不按 `sample-` 前缀或示例名称过滤，示例的用户副本仍按普通产出对账。列表展示和维护写流程保持不变；播种或后续重列失败仍属于对账未知，不能据此开放盲重试。矩阵中的在途删除、普通刷新和维护写交错由真实前端存储/保存链加 IPC 持久文档夹具验证；横幅与重试入口映射复用 `App.test.tsx` 的失败、部分提交和未知结果用例。

重命名恢复实现（[审查](https://github.com/hailingu/PlotWeave/pull/199#pullrequestreview-5238873320)）：由 `useHomeActionFeedback` 持有当前保存文档和尝试序，重命名入口在交付 `projectStore.save` 前登记该文档；复用保存链 `onRetryPersisted` 的文档身份通知。新动作清除旧登记，卸载时退订，不扩展持久化或 IPC 契约。

边界：本轮验证同一桌面实例内的入口与存储/IPC 失败语义；跨进程并发写入不属于此协调器的所有权范围。实际目录 fsync/IPC 丢包通过 IPC 替身模拟，不在运行中的用户项目上注入故障。

### 3.3 编辑器窗口 chrome：统一工具栏

标题栏与工具栏合一（macOS unified 样式），从左到右：

- **左区**：边栏开关 · 撤销/重做（跟随命令栈状态置灰）
- **中区**：项目名，点击内联重命名（更新 `project.name` + 索引）
- **右区**：＋节点（下拉：场景/节奏卡/对白/分支/分镜卡）· 导出 · 检查器开关 · **✦AI 开关**（全 chrome 唯一着品牌渐变的元素）

### 3.4 面板规则

- 三栏布局：**左栏**「大纲 / 设定集 / 资产」三分段切换；**画布**居中；**右栏**「检查器 / ✦AI」分段切换。
- 边栏、检查器宽度 220–320pt 可拖拽调节，折叠用弹簧动画；显隐状态会话内记忆。
- 右栏在「检查器 / ✦AI」之间切换或折叠时，AI 会话保持挂载；切回 AI 必须保留同一项目的消息、预览卡与回执。常驻挂载的包裹层（`.pw-ai-pane`）必须维持右栏高度链——`.pw-ai` 占满 `.pw-panel-scroll` 可视高度、历史在 `.pw-ai-thread` 内部滚动、输入区钉底、新回复自动滚入视区；包裹层自身的 `display` 声明须显式压回 `[hidden]` 隐藏（[issue #58](https://github.com/hailingu/PlotWeave/issues/58)）。
- 三栏遵循「内容在材质下滚动」：半透明材质、无 1px 硬分隔线、滚动边缘渐变过渡（HIG 材质实践）。

### 3.5 大纲视图：故事脊线的线性投影

编剧案头的四层「故事脊线」：L0 文字（梗概、人物小传/世界观文档）→ L1 分集 → L2 节拍（节奏卡）→ L3 分场（场景/对白）。四层不是四个孤立功能，而是同一棵树在不同放大倍率下的投影；大纲视图是这棵树的线性可编辑形态。

- **大纲 ⇄ 画布双视图**：大纲行 = 集 ▸ 节拍 ▸ 场景头的缩进树，与画布节点同源；大纲内拖拽排序 = 重排 `sequence` 边（走命令栈，可撤销）。选中在大纲与画布间同步高亮。
- **集 = 逻辑分类，不做显式泳道**：节点以 `episodeNo` 归属集；点击大纲中的集行，画布上该集全部节点提亮、其余节点降透明度（~30%）退后——有泳道的归属感知，无泳道的布局负担。再次点击取消聚焦。实现口径：聚焦是 `applyEpisodeFocus` 的运行态投影（非成员加 `className`，不写回真源、不入保存/撤销）；未变化的非成员复用同一投影对象（以源节点为键的 WeakMap 缓存，[issue #273](https://github.com/hailingu/PlotWeave/issues/273)，已实现）——React Flow 按 userNode 身份复用内部节点，移动一个节点不再驱动其余压暗节点重渲染（真实 React Flow 装配的渲染计数测试为证）；聚焦切换/取消、节点换集、分镜换宿主与位置变化均产生新源对象或新归集判定，投影即时更新。
- **节拍兑现状态**：节奏卡胶囊插入剧情流后未被场景承载 =「待兑现」（虚线态）；邻接承载它的场景后自动显示「✓ 兑现于 场景 n」。兑现关系由 `sequence` 边邻接派生，不落镜像字段。大纲中「待兑现」节拍与无节拍覆盖的长段场景 = 节奏漏洞，一眼可查。
- **剧本导出**：正文只由场景 + 对白生成，节拍不出现；可选「大纲注释」文件头（每集每节拍一行），默认关闭。该开关已实现（[issue #48](https://github.com/hailingu/PlotWeave/issues/48)，见 §5「剧本导出与创作大纲」）：正文与分镜附录保持不变，开启后并入「创作大纲」附录，输出节奏名称/基调/兑现状态、分支问句与全部选项去向、集归属与汇合关系；预览、复制与下载消费同一次生成结果。

### 3.6 画布左下角控件与自动排布

- **左下角控件**：React Flow 默认控件（缩放/适配/锁定），外加「自动排布」按钮（[issue #94](https://github.com/hailingu/PlotWeave/issues/94)，已实现）。按钮复用控件按钮样式（`react-flow__controls-button`），暗色/浅色界面下均可辨认，带中文 `title` 与可访问名称，鼠标与键盘均可触发；空画布禁用。
- **自动排布规则（已实现）**：主剧情流按连线方向从左至右分层（最长路径分层），分支选项出口的子节点同层纵向展开、汇合关系保留；场景下挂的分镜卡在宿主正下方左对齐成行；不连通的子图与独立节点（含图片节点）按原始位置次序纵向分区放置。间距按节点实际尺寸计算，取值顺序为 `measured` → 顶层 `width`/`height`（打开项目时落盘 `layout.size` 已还原为测量前初始尺寸）→ 各类型回退尺寸（回退宽度取卡片含 padding/border 的**外宽**，未测量卡片不因内容盒宽度偏小而重叠）；保证任意两卡片不重叠，不承诺消除任意图的全部连线交叉。相同图结构得到确定性一致的布局。
- **不变量与边界**：排布只改节点位置——节点/边的标识、数量、内容、连接端点、分支选项对应关系与分集归属不变；一次排布是命令栈上的一个撤销单元（撤销恢复全部原位置、重做恢复排布结果），无位置变化时不入栈；任一节点的宽高无法从 `measured` 或顶层 `width`/`height` 解析（新建后尚未渲染测量的节点，如 `max-content` 节拍卡）时，排布保留原布局并提示稍后重试，回退尺寸仅作纯函数兜底；成功后适配视图（`prefers-reduced-motion` 时降级为无插值即时适配，否则 400ms 动画 + `maxZoom 1`），经既有防抖保存通道落盘，重开保留。计算失败保留原布局并上浮可读错误反馈。未来可选布局参数（如方向、间距档位）为保留边界，首版不暴露配置。

## 四、节点与连线

### 4.1 节点家族：编剧侧 / 生成侧

节点的形态分族对齐生产管线「节奏卡 → 索引卡 → 剧本 → 分镜 → AI 燃料 → AI 渲染 → 剪辑成片」；外壳交互（圆角、端口、⚙️ 设置入口、选中渐变、弹簧）全部共享：

- **编剧侧 · 纸面浅色系**：节奏卡（节拍胶囊）、场景（索引卡）、对白（气泡流）、分支（岔路路标）——编剧案头物件，承载「节奏」「写什么」与「往哪去」。
- **生成侧 · 深色石板色系（`surface.slate`）**：分镜卡（监视器卡）、图片节点（生成产物监视器）、（演进）分集渲染节点——面向 AI 视频生成的物件，承载「画面」与「AI 燃料」（角色垫图 / 场景底图 / 音频 / 镜头 Prompt）。石板是内容层视觉（如 Final Cut 监视器恒为深色），浅/深外观下保持一致。

画布上扫一眼即知：浅色 = 编剧案头，深色 = 生成与画面。族色之外，每种形态同时有结构差异（不违反 HIG 包容性规则）。

> 修订说明：场景节点的旧形态为场记板。场记板是实拍片场物件（场·镜·次打板），与「前期创作 → AI 渲染 → 剪辑」的管线无对应物，且与 §7.1「次/take 属拍摄现场工具范畴，明确不做」自相矛盾，故改为编剧案头的索引卡；桥段胶囊由深色改为纸面，归入编剧侧。

### 4.2 节点形态

**节奏卡 = 节拍胶囊**（编剧侧）

- 纸面胶囊卡在剧情流上，如案头便签：⚡ + 名称 + 情绪基调（`tone`）。承载节奏而非内容，最窄，无展开身体。

**场景 = 索引卡**（编剧侧）

- 经典编剧索引卡形态：暖白纸面（双外观恒定的内容层视觉）+ 满页蓝色横格线 + 左侧红色竖边距线。
- 卡片分区对应索引卡字段：**标题栏**承载「名称 + SCENE 编号」（剧本场景头，双击名称内联改名），右端依次放「🎞 n 镜」分镜计数与 **⚙️ 设置图标——⚙️ 常驻标题栏**（`label.secondary` 色，悬停提亮），是该卡全部操作的唯一入口 → 地点/时间/内外景/天气 chip 行（`locationId` + `time` + `interior` + `weather` 的派生展示）→ 梗概（压在横格线上）→ 在场角色头像串（`characterIds` 派生）。
- 选中反馈为通用渐变描边 + 投影加深，无拍板条类专属动效。
- 「🎞 n 镜」计数派生自该场下挂的分镜卡数量（§7.2）。

**对白 = 气泡流**（编剧侧）

- 顶部窄标题行（名称 + 「n 人 · m 句」统计）；台词渲染为角色头像 + 左右交替气泡，扫一眼即知谁在说话。
- 台词中的 @ 角色渲染为带头像的 mention chip——文本 token 只存 id、按 id 实时解析（§8.1），改名不断引用。

**分支 = 岔路路标**（编剧侧）

- 虚线外框 =「此处未定」；分岔事由（`prompt`）是问句即名称；选项条右缘各带独立出口端口（动态增删，handle 绑稳定选项 id，即 `option-<选项 id>`，删选项不位移其余出口连线），「＋ 添加选项」行内完成。

**分镜卡 = 监视器卡**（生成侧）

- 深色监视器质感的卡片，从索引卡底部端口经 `attach` 边**垂直下挂**（派生从属，不参与横向剧情流），紧贴宿主卡正下方排列，一场可挂多张。
- 卡片字段对应 AI 燃料：**镜号 + 景别**标题行（右端常驻 ⚙️）→ 画面描述 → 镜头 Prompt → 引用位（角色垫图 / 场景底图 / 音频缩略 chip；引用走 `spec.refs`——`kind` 表达用途，`assetId` 明确指向本项目 `assets.byId`，缩略图/媒体内容按项目资产实时解析，见数据模型 §4.2）。缩略图生命周期（[issue #131](https://github.com/hailingu/PlotWeave/issues/131)，已实现）：换绑即清理旧预览——新资产解析在途或失败都不得以旧资产的图冒充当前引用（图文错配）；媒体不可读（解析失败或图像加载失败）以 ⚠ 标记呈现（悬停 title 带 relPath 保持可定位），chip 回退纯文本。图片节点产物区同款语义（在途清空、失败显示「产物媒体无法读取」占位）。
- 引用读取防护（[issue #130](https://github.com/hailingu/PlotWeave/issues/130)，已实现）：只按资产桶自有属性解析引用，`constructor` / `toString` / `__proto__` 等继承属性不算资产；同名自有合法资产仍正常展示。目标缺失、条目为空或 MIME 缺失/非字符串时，当前 chip 保留原引用 ID 并显示 ⚠，悬停说明「引用资产缺失/不可用」及 ID，不影响同卡其他引用。资产失效即清除旧缩略图，恢复合法条目后正常显示；合法音频与自由文本位保持纯文本展示。
- 首版为结构占位：字段与引用位齐备，拖拽建立引用与渲染联动随 §13 演进。

**图片节点 = 生成产物监视器**（生成侧，数据模型 §13 文生图首版）

- 深色石板卡片，**自由摆放在画布上、不参与任何连线**（无端口）：生成产物是非叙事物件，由用户手动泊位（如贴在对应分镜卡旁作关键帧）。
- 卡片分区：**IMAGE 徽标 + 尺寸 chip + 作业状态**标题行（右端常驻 ⚙️）→ Prompt 预览（压在监视器底色上）→ **产物区**（生成图像封面 / 生成中 / 空态「尚未生成」/ 悬空引用占位——`outputs.primary` 的资产已删时按缺失展示，§8.2.3）。
- ⚙️ 面板承载：Prompt（多行）、模型（三层过滤下拉，空 = 跟随设置页默认图像模型）、尺寸（方图 / 竖版·短剧 / 横版三档）、「✦ 生成图片 / ■ 取消」与失败文案。生成完成前输入（Prompt/模型/尺寸）变化即丢弃结果（输入签名守护，§13），横幅提示。取消为协作式：本地立即清作业（可马上重新生成），取消请求 IPC 被拒且该节点尚未启动后续作业、宿主仍存活时呈现失败诊断——文案明示远端生成可能继续并计费、结果到达时仍将被丢弃，不承诺已停止付费请求（[issue #160](https://github.com/hailingu/PlotWeave/issues/160)，已实现）。重新生成后，旧取消请求的迟到失败仅经控制台留痕，不覆盖后续作业的运行态、完成结果或失败诊断；删除节点（含撤销复活）和编辑器卸载后同样不再显示旧取消错误（[PR #200 审查修复](https://github.com/hailingu/PlotWeave/pull/200#discussion_r4042402798)）。删除时也会清除此前已显示的取消、生成或准备阶段错误；撤销删除后的节点回到空闲，可重新生成，幸存节点的诊断保持不变（[后续审查](https://github.com/hailingu/PlotWeave/pull/200#discussion_r4044155985)）。

### 4.3 外壳交互（全部节点共享）

- **名称在卡片头部**：场景 = 索引卡标题栏（名称 + SCENE 编号 + 🎞 镜数 + ⚙️）、对白 = 标题行、节奏卡/分支正文即名字、分镜卡 = 镜号标题行。双击名称内联改名（发 `update_node_meta` 改 `meta.label`；**分支例外**——标题由 `spec.prompt` 派生、不落 `meta.label` 镜像，改名走 `update_node_spec` 改 prompt；**分镜卡无内联改名**——镜号标题由 `spec.shotNo` 派生，镜号在 ⚙️ 面板内编辑）。
- **选中 = 渐变描边 + 投影加深**（五类节点同一反馈，无专属动效）；不设独立浮动工具栏、不设操作条。每类节点的**标题行/胶囊右端常驻 ⚙️ 设置图标**（`label.secondary` 色，悬停提亮）：场景/分镜卡 = 标题栏右端，对白/分支 = 标题行右端，节奏卡 = 胶囊右端。全部节点操作（重命名/复制/类型专属动作/删除）收进 ⚙️ 打开的设置面板，不在卡片上平铺按钮；全部操作同时可从右键上下文菜单到达。
- **⚙️ 设置面板 = 节点编辑器**：点 ⚙️ 或双击卡片，在卡片下方以卡片为锚点弹簧展开（半透明 blur），失焦收起。面板承载该类型的全部字段（场景：名称/场次/地点/时间/内外景/天气/梗概/出场角色——场次可改，供插入与重排后修正编号，导出与卡片头均消费；对白：台词列表 + @ 提及选择器；节奏卡：名称 + 基调——「内容」即节点标题 `meta.label`，BeatSpec 无正文字段；分支：问句 + 选项增删排序；分镜卡：镜号/景别/画面描述/镜头 Prompt/引用位），底部为 ⧉ 复制与 🗑 删除（`danger` 色；删除可撤销，无需确认对话框）。编辑即命令——非组合输入的修改实时提交，映射到 `update_node_spec` / `update_node_meta`，无「保存」按钮。
- **组合输入（#42，已实现）**：节点设置面板全部自由文本 `input`/`textarea` 共用 `useCompositionSafeValue`。拼音等 IME 组合期间只更新本地草稿，不向节点逐键提交，也不把滞后的节点值回写到输入框；`compositionend` 提交最终文本，尾随同值 input 不重复提交。非组合态继续即时编辑，撤销/重做产生的外部值在非组合态同步。
- **端口在左右边缘中点**：拖拽连线时实时校验——可连 = `connection.valid` 绿色发光放大，非法 = `connection.invalid` 红色（自环/成环，对齐 `isValidConnection`，§4.3）；连线拖拽中节点主体可作磁吸目标。
- **状态**：悬停 translateY(-1px) + 描边加深；选中 = 品牌渐变描边 + 投影加深；AI 改动（actor=agent）节点右上角 ✦ 角标，用户查看后消退；失效引用（设定被删）灰虚线角标 + 删除线，不自动清除（§6/§8.2）。

### 4.4 连线

- `sequence`：中性灰细贝塞尔，无标签，走横向剧情流。
- `attach`：索引卡底部端口 → 分镜卡顶部端口的派生从属边——细虚线、无标签、垂直下挂。画布方向语言：**横向 = 剧情顺序，垂直 = 派生从属**。
- `branch`：品牌渐变描边 + 线上选项胶囊；胶囊文案与分支选项同源（不落第二份拷贝，§8.1 禁止镜像字段）。#18 已实现运行态实时订阅：按稳定 `sourceHandle` 解析源节点选项 id，改名及撤销/重做立即更新胶囊，运行态也不保留 `optionLabel`；悬空句柄或非分支源回退空文案，选项删除仍级联断边。

## 五、全局联动：设定集 → 节点 → 成片

- **设定集 ⇄ 节点双向可见**：索引卡的时空戳/头像串、对白气泡头像、检查器字段，全部是设定集引用的派生视图——改设定集一处，全部同时生效；点击头像 chip 反向定位设定集条目；设定被删时按「失效引用」样式展示（§8.2.3）。
- **设定集「文档」条目（issue 56，已实现）**：人物小传、世界观、术语表等自由文本（📄 图标），与结构化条目（角色/地点）互相关联（小传挂在角色名下）。左栏设定集分段列出全部文档，点击行打开编辑器弹窗：标题与长篇正文阅读/编辑、关联角色/地点 chips 切换；「保存」一次派发一条 `update_document` 语义的命令入栈（可撤销），Esc/关闭放弃编辑，保存后随项目自动落盘。弹窗是一次模态编辑会话（[issue #126](https://github.com/hailingu/PlotWeave/issues/126)，已实现）：打开期间全局撤销/重做/删除快捷键挂起——输入框内保持原生文本撤销，非输入焦点仅 Esc 放行，命令栈不在弹窗底下被改写，保存不会把已撤销的旧草稿写回；底层文档若仍经残余路径变化，未编辑的草稿跟随刷新、已编辑的草稿保留用户输入，底层文档被删除时弹窗随 id 解析失败自动关闭并清空挂载 id（模态会话结束，全局快捷键恢复）。文档是写作原料，条目是蒸馏出的可引用实体；文档全文进入 AI 上下文快照的按需读取范围（`get_document`，§6）。
- **设定条目人工详情编辑（issue 95，已实现）**：角色/地点条目行新增常显折叠钮（`aria-expanded` 语义），点击在侧栏内展开详情表单——名称单行输入、小传/备注多行输入（支持换行与粘贴），字段直接映射既有模型（`bio`/`note`），不建平行文本存储；「保存」一次派发一条 `update_character`/`update_location` 语义的命令入栈（可撤销），保存后收起；「取消」/Esc 放弃草稿且不改已提交内容，组合输入中的 Esc 不误关表单。名称去空白后为空禁用保存（与新增占位名/行内改名的非空契约一致）。空项目显示新增引导文案，空白区域不成为死角；新增角色/地点后自动展开新条目表单并聚焦名称字段。人工编辑不依赖 AI 配置，AI 生成的条目同样可改；保存只整体替换目标实体，条目 id、头像渐变与未编辑字段不变，画布引用按 id 解析即时反映新名称。文档（长篇正文）继续经列表行打开既有编辑器弹窗（见上条）。
- **建立引用 = 拖拽**：从左栏把角色/地点拖上节点；拖上空画布直接生成预填的场景/对白节点。
- **通往成片**：画布剧情流对齐「剧本 + 分镜（创意核心）→ 角色垫图 / 场景底图 / 音频 / 镜头 Prompt（AI 燃料）→ AI 视频大模型（渲染引擎）→ 剪辑软件拼装 → 成片」的管线。首版收敛到「导出剧本 + 分镜卡（含 Prompt 与引用位）」；数据模型 §13 的渲染节点（分集视频生成）未来作为生成侧新节点类型接入同一画布骨架——引用类输入走边、参数走 `spec.params`，界面骨架无需改变。
- **设定集 ≠ 设置页**：设定集是项目内实体（左栏）；设置页是应用级 BYOK provider/模型配置（本文件 §8.2）。
- **剧本导出与创作大纲**（[issue #48](https://github.com/hailingu/PlotWeave/issues/48)，已实现）：导出对话框展示本次导出范围（集/场/对白/节拍/分支计数），以「创作大纲」开关（默认关闭）决定是否并入大纲附录；开关只切换同一次生成结果的文本，不改动画布或项目实体。生成器（`src/editor/exportScript.ts` + `src/editor/exportOutline.ts`）的分工与语义：
  - **正文**只由场景 + 对白生成，节拍/分支不进正文；分镜卡仍以附录按宿主场分组输出。节奏卡只有名称与基调，不展开为剧情正文。
  - **大纲行层级**（[PR #81 层级修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5178974608)）：节拍与场景为第 0 层，对白、分支问句与未接入剧情流的分段标记为第 1 层，分支选项为第 2 层；Markdown 每级缩进两个空格。层级按类型固定，不随节点是否连通或分支嵌套深度累加。
  - **大纲行分类与空态提示**（[PR #81 分类与空态修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5179090779)）：结构化大纲以 `branch` 标识分支问句，普通节点为 `node`、选项为 `option`、分段标记为 `marker`；分类不随连通性或选项数量改变。无场景/对白但存在节拍/分支时，关闭大纲的提示引导开启附录；空画布或只有分镜/图片时，开关两态均提示「暂无可导出的场景、对白、节奏或分支」。提示随当前导出模型更新，开关仍决定是否并入附录。
  - **跨集连通性**（[PR #81 跨集端点修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5179200982)）：是否接入剧情流按全画布中两端均存在的叙事边判断；跨集（含已分集与未分集之间）`sequence` / `branch` 的源和目标均视为已连通，在本组没有前驱时作为本组入口参与排序，不进入「未接入剧情流」分段。外部边不作为组内排序依赖，也不增加组内汇合数；悬空边、分镜/图片端点及 `attach` 不建立叙事连通性。每次导出均按当前连线重新派生。
  - **大纲是故事脊线的语义投影，不是画布坐标投影**：组内按 `sequence` 与 `branch` 的共同先后依赖排序：只有全部组内前驱均已列出的节点才可输出，当前可输出的并列节点按画布 x 序、同 x 按 id 排序；未接入剧情流的节点仍在独立分段按 x/id 排序。移动卡片不能让分支目标跑到问句及选项之前，汇合点在全部前驱之后输出一次（[PR #81 分支先后关系修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5178822678)）；`attach` 下挂边不参与剧情流，分镜卡与图片节点不进大纲。汇合点只作一次主线成员，并在行内标注「汇合 n 条路径」：按组内 `sequence` 与 `branch` 入边逐条计数，同一分支不同选项直接指向同一目标也分别计入；跨集入边、悬空来源、`attach` 与自环不增加组内汇合数（[PR #81 审查修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5178633425)）；组内没有叙事入边的节点标注「入口」，无任何叙事边的节点列在「（未接入剧情流）」分段下，不被静默丢弃。
  - **集归属**沿用 `episodeNo`（未分集殿底），集标题取文档级 `episodeTitles`；分支行输出问句，其下逐项列出全部选项与去向（目标节点的可读标签，跨集目标同样出可读名称；同一选项连向多个目标时逐个列出，不静默丢路径），未连线标「（未连线）」、目标已删标「（目标已删除）」——替代路径不被平铺成一条已发生的剧情。选项目标为节奏卡时沿用该节拍的兑现状态（与节拍自身行同口径），同一导出内不自相矛盾。
  - **复制回执**（[PR #81 审查修复](https://github.com/hailingu/PlotWeave/pull/81#pullrequestreview-5178633425)）：切换大纲、导出文本更新、再次复制或关闭对话框时，清除旧回执并使进行中的旧请求失效。旧请求随后成功、失败或超时，均不能更新当前按钮或选中新预览；当前请求成功仍限时展示「✓ 已复制」，失败或超时仍全选当前预览供手动复制。已交给系统的剪贴板写入无法取消，这里保证的是回执与选区的请求归属。
  - **导出模型的生成时机**（[issue #158](https://github.com/hailingu/PlotWeave/issues/158)，已实现）：语义收口为**实时预览**——模型按内容依赖缓存（节点/连线/设定/资产/集标题/项目名），对话框打开期间无关布局渲染复用同一模型、不逐渲染重建；内容任一变化即重建，预览、复制与下载始终共读同一份。资产取响应式文档状态而非 ref 镜像，保证资产变化纳入依赖。
  - **边界**：本期不做 PDF/Word/完整项目备份格式，不自动生成缺失正文，也不提供「选择一条路线生成线性剧本」的转换。
- **AI 可经对话维护角色/地点（issue 44）与设定文档（issue 56）**：对话中要求补充设定集时，AI 以命令产出真实的改动——预览卡列出新增/修改的实体与字段变化及引用绑定，确认后左栏即时可见、场景与对白按实体引用展示；实体改动与画布绑定是同一撤销单元（⌘Z 同时恢复两侧）。修改既有实体须精确 id，未提及字段保持不变；设定文档（长篇小传/世界观/术语表）同样可经 `upsert_document` 新建或修改（改写前先经 `get_document` 读取现有全文，正文整体替换），文档改动与节点/实体折叠为同一复合命令，预览卡逐项列出。道具仍不对 AI 开放，助手可提供文本草稿由用户手动录入，不以分镜卡/场景卡替代设定档案。

## 六、AI 对话面板与改动预览

右栏「✦AI」分段。核心约束来自数据模型 §12：Agent 只产出命令、写操作执行前必须批量预览、undo 始终兜底。

- **对话气泡归属清晰**：用户 = 品牌渐变右气泡；Agent = 浅色左气泡带 ✦。
- **改动预览卡是命令的翻译**：逐项列出受影响节点与变更类型（创建/修改/连线/删除，issue 44 起含设定实体的创建/修改及其字段变化、引用绑定，issue 56 起含设定文档），整卡 = 一个 `batch` 命令——执行后是一步撤销，撤销即整批回滚（实体、文档与画布绑定两侧同时恢复）。执行前画布与设定集零副作用。
- **字段协议同源 + 校验闭环**（issue 41）：节点字段表由 `ai/nodeFields.ts` 单一来源生成，系统提示、工具描述与校验白名单共用（如节奏卡只允许 `name`/`tone`/`episodeNo`）；设定实体与文档字段表同构（`ai/entityFields.ts`，issue 44/56）。批次被校验拒绝时，具体错误清单按 tool 协议或 user 消息回喂模型有限次纠错重试，耗尽后保留错误预览卡、画布保持不变，绝不静默丢弃或改写字段。校验拒绝卡不可执行，但可逐张忽略——忽略只受回合 busy 约束、独立于校验状态，处置（dismissed）随会话落盘并按「后续对话识别执行状态」（issue #73）口径回喂模型（[issue #151](https://github.com/hailingu/PlotWeave/issues/151)，已实现）；不为清理单卡动用整段会话清空。
- **完整创建形状**（[issue #75](https://github.com/hailingu/PlotWeave/issues/75)，已实现）：单写工具与 `batch.commands` 向模型提供显式参数 schema，包含操作、节点类型、必填字段及对白行、分支选项、分镜引用的嵌套结构。系统提示同时给出可解析的完整场景插入、角色与对白插入示例；首次请求和纠正重试均可参照。对白 `speaker` 使用已确认角色 id 或先行创建角色的批内 `ref`，动作行不带 speaker。示例 id 是占位值，模型须结合当前快照替换，不能照抄为真实目标；示例经实际工具 schema 和应用校验、执行链路验证。
- **顺序插入的连线语义**（[issue #75](https://github.com/hailingu/PlotWeave/issues/75)，已实现为模型指引）：在 A 唯一顺序连接 B 时要求「在 A 后创建」默认提议同批断开 A→B、创建 C、连接 A→C→B；原直连会绕过新内容，应在该批次中移除。没有后继时仅创建并连接 A→C；用户明确要求额外路径时保留原路径，多后继或分支归属不明时先澄清。对白是剧情流 `sequence`，只有场景下挂分镜使用 `attach`。断开与创建连线都展示在待确认预览中，确认后整批生效、一步撤销。通用图模型仍支持多出口，不通过全局清理自动修正现有项目，模型是否遵循插入意图仍需检查预览。
- **明确操作的交付收敛**（[issue #75](https://github.com/hailingu/PlotWeave/issues/75)、[issue #91](https://github.com/hailingu/PlotWeave/issues/91)，已实现）：对增加分镜、创建场景等显式修改请求，纯文本说明也进入有限次纠正；模型主动给出批次或声称有预览（含「确认后预览会展示……」式确认门控承诺）后，同样不能以无批次的操作承诺结束。词表识别不再逐个追补口语动词（如「扩写」）：输入已含规范动作动词时本地直接判定，其余输入（含讨论、提问与「不要解释，直接扩写」这类否定辖域表达）先经一次轻量 query 改写调用归一化判定——否定辖域与「特别」这类偶发子串由改写调用判别，讨论片段不否决改写（首轮评审）；改写回复为结构化 JSON（`{"action":true,"query":"…"}` / `{"action":false}`），query 须以规范动词开头（与词表同源），分类标记、解释文字、非动词开头或坏 JSON 一律按非动作回退（第二/五轮评审）；「确认后预览不会显示…」等否定式预览描述不构成交付承诺，且承诺候选逐一校验、首候选被否定不掩盖后续正向承诺（第三/五轮评审）；明确暂不操作由动词快速路径加词表否决、以及改写判为非动作回退承担，回合照常进行。工具解析失败整批拒绝，空批次不可执行，合法子集不能掩盖同轮失败。与既有校验纠错共享首次 + 3 次重试，读取最多 3 轮；无可用批次时在所属助手消息内明确提示「本轮未生成可执行改动」及补充目标／重试的下一步，并保留模型提出的澄清问题。普通讨论、用法提问和明确暂不操作的输入继续允许纯文本结束。这里的保守识别只控制纠正，不从自然语言直接写入，也不重放历史批次；助手正文回显的 `[应用批次记录]`／`executed` JSON 不是命令，不构成成功交付也不产生预览卡。回归矩阵与边界见 §6.1。
- **危险操作升级**：预览卡中涉及删除的项用 `danger` 色标出并置顶；删除类变更永远需要显式确认，不提供「自动执行」开关。
- **未知类型反馈（[issue #49](https://github.com/hailingu/PlotWeave/issues/49)，已实现）**：模型输出或历史待执行卡中的未知节点/连线类型，包括 `toString`、`constructor`、`__proto__` 等原型属性名，均返回可读校验问题并整批拒绝；空载荷同样检查。不显示函数源码式预览标签，不把非法类型解释为分镜卡或剧情流边；拒绝时画布、撤销栈与提交计数保持不变，纠正为合法类型后可按原流程重新预览和执行。
- **上下文摘要**：输入区常驻「了解当前画布」标识——默认给 LLM 压缩快照（id/type/label/连接关系），对白分别显示台词句数与旁白/动作条数，详情由读工具按需拉取（§12.2）；设定集清单（角色/地点 id、名称、小传/备注）由 `get_settings_snapshot` 按需读取（issue 44），文档只列 id 与标题，长篇正文经 `get_document` 按文档 id 读取全文（issue 56），避免长文本进入画布快照膨胀上下文。
- **后续对话识别执行状态（[issue #73](https://github.com/hailingu/PlotWeave/issues/73)，已实现）**：每次发送都将历史预览卡的待确认、校验拒绝、执行失败、已忽略或曾执行成功状态随对应助手消息传给模型，包括较早卡片在后续轮次才被确认的情况；关闭画布摘要不删除这些对话状态。执行失败记录可随会话恢复，重试成功或忽略后清除旧失败。模型能区分「已产出命令」与「只给文本建议」，并区分历史执行和当前效果：曾执行不代表已保存或当前内容未被撤销、修改，续写前按需读取当前节点，不凭历史记录重复执行。历史摘要有界裁剪，完整预览、确认与撤销流程保持原有交互。
- **模型选择器与设置入口**（[issue #87](https://github.com/hailingu/PlotWeave/issues/87)）：面板顶栏同一行放模型选择器与常驻设置按钮；选择器只列三层过滤后的可用模型（在内置目录或自定义条目 → provider 已配置 → 未被禁用，§10.3），窄栏下可收缩（不把入口推出视野）；未配置任何 provider 时显示引导卡片，一键去设置页。设置按钮不依赖配置状态——配置齐全后引导卡片消失，会话读取失败时聊天操作区停用但入口保留，两者之下它都是 ⌘, 快捷键之外唯一的可见设置回访入口；点击与 ⌘, 语义一致（同一主窗口切换，关闭后回到原界面）。
- **新会话入口**（[issue #89](https://github.com/hailingu/PlotWeave/issues/89)）：顶栏「新会话」按钮两步确认后清空当前项目的会话线程，空会话经既有保存通道落盘——重开项目不复活旧历史，容量裁剪（§6.2）与归一化语义不受影响。清空不可 ⌘Z（不在画布撤销栈内），未确认预览卡随会话一并丢弃，画布已执行改动不回滚（执行是画布事实，撤销走画布撤销栈）。空会话或回合进行中（busy）禁用：busy 门闸保证清空时刻回合注册表必空，迟到回复不可能经重挂载认领写入新会话；会话读取失败态不出现该入口（失败态禁止一切会话写入）。
- **在途回合取消（[issue #154](https://github.com/hailingu/PlotWeave/issues/154)，已实现）**：回合进行中（busy）输入行切换为「取消」按钮——在途的多轮 tool-calling 循环可停止：取消是协作式的（`agentLoop` 在各检查点查询取消信号并停止后续循环），在途的那一次 `llm_chat` 网络请求不被中止，会继续跑完、其结果随回合一起被丢弃（owner 裁决：仅停止循环，不新增后端取消 IPC）。取消后立即可发下一轮：世代守卫使旧轮迟到的结果不被交付——不覆盖新轮次、不误形成预览；离开面板（#63 导航）后迟到的已取消结果仍按世代丢弃，不复活旧轮。用户消息保留，追加一条「已取消」note 回执随会话持久化（不进入喂给模型的历史）。取消回执之外的既有成功/失败/纠错语义不变。
- **历史与失败提示**（[issue #47](https://github.com/hailingu/PlotWeave/issues/47)、[PR #57](https://github.com/hailingu/PlotWeave/pull/57)）：按单应用实例使用，重开项目读取唯一会话主文件，项目 A/B 隔离。主文件落盘总量最多 200 条（[issue #64](https://github.com/hailingu/PlotWeave/issues/64)、[PR #85](https://github.com/hailingu/PlotWeave/pull/85)）：可执行待确认卡优先占容量，其余额度保留最新历史，按原时间线展示。待确认卡自身超出 200 张时只保留最新 200 张；被裁掉的旧提案重开后不再恢复，项目打开期间的内存会话与滚动不受影响。容量裁剪只发生在写入主文件的落盘边界——设置页往返的重挂载与保存失败后的首页重开都恢复完整内存会话，不受裁剪影响。保留下来的待确认卡重开后按当前画布重校验，仍需再次确认执行；状态矩阵及边界见 §6.2。保存失败在消息区提示，内存历史与错误跨设置页、首页导航保留；后续变更或重开保留会话可重试，成功清除提示。不写恢复副本、不做定时重试，也不显示副本选源、序号冲突或分叉调和状态。正常关闭窗口/⌘Q/Dock「退出」等待保存，每项目最多重试一次；失败保留窗口并提示检查磁盘后重试退出。强制终止可能丢失未保存内容。坏条目隔离并提示。读取失败时显示原因和“请检查磁盘后重新打开项目”，AI 发送与执行停用，检查器及画布继续可用；进出设置页不解除限制，重开成功读取后恢复。文件不存在仍按空历史正常聊天。卡片执行回执仍以画布提交计数核对：未确认落盘不虚报已保存的执行，已落盘批次恢复为历史改动，不重复执行、不承诺跨重启撤销；重启不自动重发模型请求。

### 6.2 会话落盘总量回归矩阵（issue #64）

关联 [issue #64](https://github.com/hailingu/PlotWeave/issues/64) 与 [PR #85 评审](https://github.com/hailingu/PlotWeave/pull/85#pullrequestreview-5181315757)。保存管线分两层：`persistedEntries`（session.ts）做落盘形态映射（运行时标注剥离、未确认执行卡降级、关联回执剔除），`diskSessionOf` 在 `aiSessionStore` 写入主文件（或浏览器内存回退等价物）的落盘边界施加总量容量并拥有顺序不变量——总量最多 200 条，优先保留最新的可执行待执行卡，再用最新普通历史补齐容量，最终按原时间线输出。待执行卡也占用容量；其自身超过 200 张时，最旧提案随落盘裁剪，重开不再恢复。面板保存通道与进程内快照（设置页重挂载种子、保存失败保留、退出冲刷待写重试）持全量形态；内存会话与加载归一化不裁剪；旧文件仍全量加载，实际变更保存时才收敛。下列用例在生产代码变更前选定。

| 前置状态 | 动作／事件顺序 | 预期可见结果 | 跨转换不变量及所有者 | 对应验证 |
| --- | --- | --- | --- | --- |
| 无优先卡，条目数小于、等于或超过 200 | 保存 | 界内完整保留，超额保留最新 200 条 | 落盘边界 `diskSessionOf`：总量 ≤200、输入不变 | `useAiSessionPersistence.test.ts`；`aiSessionStore.tauri.test.ts` |
| 多张较旧或较新的合法 pending 卡与普通历史混合 | 保存 → JSON → 加载 | 待执行卡优先占容量，剩余为最新历史，顺序不变且不重复 | 落盘边界：最多 200 张待执行卡不因普通聊天被淘汰；加载保留命令载荷 | `useAiSessionPersistence.cap.test.ts` |
| 待执行卡为 199／200／201 张，后续另有 200 条历史 | 保存 | 分别保留 199 卡+1 历史、200 卡、最新 200 卡 | 落盘边界：优先条目也受总上限约束；超过容量从最旧提案裁剪 | `useAiSessionPersistence.cap.test.ts` |
| 两张未确认执行卡与尾部关联回执 | 降级 pending → 剔除回执 → 分配容量 → 重载 | 两卡占用两条容量，回执消失，命令与 `aiRevisionAfter` 保留 | 形态映射拥有对账身份；既有恢复逻辑按画布计数决定 pending／历史 executed，不自动重放 | 新增 cap 测试；既有 `AiThread.context.test.tsx` |
| 旧卡变为 dismissed、已确认 executed 或校验拒绝 | 保存 | 卡不再占优先容量，普通历史可补入 | 落盘边界按当前卡状态选择；内存卡状态不被保存改写 | cap 测试的状态转换与拒绝卡用例 |
| 旧文件超过 200 条 | 加载 → 首次挂载 → 用户编辑 → 保存 → 重载 | 加载和挂载不改文件，编辑保存后最多 200 条 | `normalizeAiSession` 不裁剪；hook 挂载不自动破坏旧文件 | `useAiSessionPersistence.cap.test.ts` |
| 保存 I/O 失败 | 变更保存失败 → 后续变更重试成功 | 错误可见，成功后清除 | hook 不清空内存历史，容量选择不修改输入 | 既有持久化失败测试与 cap 输入不变断言 |
| 会话超过 200 条并成功保存 | 保存 → 打开并关闭设置页（重挂载种子） | 重挂载会话仍为全量形态，较旧进程内历史不消失 | 快照持全量；容量只在写入主文件时施加（所有者：aiSessionStore 落盘边界） | `useAiSessionPersistence.test.ts` 全量形态用例；既有 `App.test.tsx` 设置页往返用例 |

## 七、专业管线映射：剧本 / 分镜 / 场记

### 7.1 层级对齐

专业制作为三级：剧本（编剧：故事结构 + 场景头）→ 分镜脚本（导演：每场拆镜头——镜号/景别/运镜/画面/对应台词）→ 场记（拍摄期：场记板本身是 场·镜·次 三级编号）。PlotWeave 是前期创作工具：「次/take」、场记单、通告单属拍摄现场工具范畴，明确不做（原则 5）。

### 7.2 组合方案：分镜卡上画布

分镜不再藏进独立层级，而是作为生成侧一等节点接入同一画布：

- **编剧侧**：索引卡 / 节奏卡 / 对白 / 分支编织故事结构。
- **生成侧**：分镜卡经 `attach` 边垂直下挂在索引卡正下方（§4.4），每张卡 = 一个镜头（镜号 + 景别 + 画面描述 + 镜头 Prompt + 垫图/底图/音频引用位）。索引卡标题栏的「🎞 n 镜」计数即派生自下挂分镜卡数量。

符合创作流：先定结构，再逐场拆镜；拆出来的每个镜头直接携带 AI 燃料，剧情流自然收敛到渲染端。

### 7.3 场记（场次）之间的三种联动

| 联动 | 现实对应 | PlotWeave 承载 | 状态 |
| --- | --- | --- | --- |
| 叙事联动 | 场次顺序与分岔 | sequence / branch 边 | 首版 |
| 接戏联动 | 角色/地点/道具跨场连续（场记接戏照） | 设定集引用；连续性检查提示 | 首版 + 演进 |
| 统筹联动 | 同地点/同卡司集中拍摄（通告单） | 按地点/角色聚类的分组视图 | 演进 |

### 7.4 首版边界

首版分镜卡为结构占位：字段（镜号/景别/画面描述/镜头 Prompt）与引用位齐备，拖拽建立引用、AI 渲染联动留待 §13 演进。「集」（短剧分集）的持久化已定稿为文档级 `episodeTitles: Record<number, string>`（数据模型 §3/§4.1，v1 定稿即生效），不随分镜卡演进再评审。

## 八、资产库面板与设置页

### 8.1 资产库面板：按影视美术部门分类

左栏「资产」分段 = 个人资产库（跨项目，§7.1）。分类对齐真实剧组美术侧分工：

| 类别 | kind | 内容 | 结构 |
| --- | --- | --- | --- |
| 角色设定 | `character` | 三视图、表情集、定妆/状态变体 | 视角走 `view`；成套走 `groupId` |
| 场景设定 | `location` | 气氛图、堪景照、平面/机位图 | 多角度同理编组 |
| 服化道 | `wardrobe` | 服装、妆发、手持/关键道具 | 现实剧组服化道本为一个部门 |
| 色彩光影 | `colorlight` | 色彩脚本（color script）、光影氛围参考 | 色彩脚本按场次排列展示 |
| 风格参考 | `reference` | mood board、参考片截图 | |
| 其他 | `other` | 兜底 | 避免强制归类 |

- 面板结构：分类列表（带计数）→ 类别内筛选（角色类出现视角/表情/定妆筛选条）→ 编组卡（如「女主·林晚」三视图 + 表情集）；`tags` 只补自由维度（题材/风格）。
- **色彩脚本专属呈现**：按场次横向排列色调 key；与画布场次的关联走资产引用模型，首版只做展示与手动关联，不建状态机。
- **标签编辑保存语义（[issue #124](https://github.com/hailingu/PlotWeave/issues/124)、[PR #176](https://github.com/hailingu/PlotWeave/pull/176)）**：已实现以下行为。
  - **编辑身份与未编辑失焦**：输入以显式脏状态区分本轮编辑、保留的提交草稿和无草稿显示；值相等不能替代编辑身份。无本轮编辑时，仅仍保留的失败草稿可以失焦重试；普通聚焦/失焦始终不写库，包括新面板读到 A、旧面板随后保存 B 的跨挂载窗口。此时若本实例没有待完成的标签提交，就从门面持久化快照只读同步 tags；单纯显示陈旧值不会自动成为撤回意图。
  - **真实编辑与回退**：输入按中英文逗号解析、去空白、滤空。真实编辑或失败草稿重试只有在解析值同时与本地值、门面基线一致，且门面没有在途更新、当前实例没有目标不同的待完成提交时，才免于写入并解除自身错误。明确撤回到 A 时，只要旧实例的 B 仍在途，就必须把 A 排在其后；不能仅凭当前实例的空队列放行。
  - **跨挂载顺序与成功基线**：每次真实标签提交立即进入 `libraryStore.updateMeta` 的门面队列；同一资产的更新和删除串行到达存储，不同资产互不阻塞，改名同走此口。组件不再另设延迟发出的提交链，避免旧实例排队中的 C 在新实例 D 之后才进入门面而覆盖 D。每次成功落盘（含发起方已卸载、被更新提交取代的成功）都推进门面持久化快照；`persistedSnapshot` 查询基线，`hasPendingOperation` 查询跨挂载的在途更新或删除。
  - **显示与草稿**：组件只采纳最新提交代际的响应；成功以 tags 字段级合并同步本地，保留并发乐观改名。已保存值变化时，无编辑中的输入收敛显示；显式 dirty 草稿（包括编辑中改回旧值）不被迟到响应抢占。失败保留输入；保留的失败草稿即使与旧本地 tags 恰好相同，再次失焦仍可重试。
  - **错误归属**：标签错误以独立横幅行按资产逐个记录未解决集合（分号分隔），与导入/列表错误分属状态槽，同文案也互不误清。任一资产成功或明确的无写入回退只解除自身错误。分类切换丢弃失败草稿后，未编辑失焦只能同步已保存值，不能将陈旧显示当作失败草稿重试，也不冒充修改已保存而清除失败提示。
  - **确认删除**：`remove` 排在同一资产已发起的更新之后，前序更新失败也继续删除，避免删除抢先导致排队更新失去目标。确认时即清除该资产标签错误、失效旧标签响应，随后移除行；取消确认不改变标签提交或错误。删除成功清除持久化快照，失败保留此前成功基线并显示删除错误；沿用乐观移除行为，失败后的存储条目在重新加载列表时恢复。其他资产的提交和错误不受影响。
  - **保留边界**：跨挂载快照在未编辑失焦时同步，当前未订阅旧实例成功后的即时刷新；用户在此之前基于陈旧显示做出的真实编辑仍按最后编辑意图写入。分类切换卸载行组件会丢弃未提交草稿（既有行为），草稿跨挂载持久化仍待独立演进。
- **异常反馈（#10、#25、#29、[issue #137](https://github.com/hailingu/PlotWeave/issues/137)）**：资产重做复验失败显示错误并保留可重试命令；库事务冲突资产不可预览、不可导入。图库面板显示可展开详情、可关闭的“图库数据提示”，承接读取和各写操作返回的 `warnings`；同一会话内去重并跨面板挂载保留，后续正常响应不自动清除，用户关闭后新诊断可再次显示。删除隔离区待清理状态（[issue #135](https://github.com/hailingu/PlotWeave/issues/135)，已实现）同样进该提示通道，且按语义分两类呈现（PR #222 评审修订）：索引已提交、仅能力保留的待释放项显示「删除隔离区待清理（N 项）」、影响（磁盘空间尚未释放——不误报成媒体已物理删除/空间已回收）与恢复指引（退出后清理 `library/assets/.trash/` 并同步移除 `asset-delete-journal.json` 对应条目）——**该目录级删除指引仅在当前快照没有证据项、且本会话未收到任何有效图库警告时给出**（[PR #222 审查修订](https://github.com/hailingu/PlotWeave/pull/222#discussion_r4052500356)：索引仍引用的冲突可能只存在于 `warnings`，不能只看 `cleanupPending`；警告没有结构化类别，因此所有有效警告均保守暂停指引）。会话清理保护独立于提示可见性，关闭提示、后续干净/缺失响应、失败或迟到响应均不解除；先备份并人工核对，完全退出重启后由新一轮恢复诊断重新判断。代价是一次性修复警告也会让本会话暂缓目录级清理，正常图库编辑不受影响；冲突/待核对类（身份异常/不符/被占用、`indexUncertain` 裸隔离名）显示「待人工核对的删除事务（N 项）」并明示保留现场——这些是仅存原媒体与核对证据，**不附任何删除指引**（分类 fail-safe：未识别形态默认归入此类）。`cleanupPending` 内容仅随各操作（列表/导入/更新/删除/组命令）响应或恢复事件携带的更新 `diagnosticsRevision` 整体替换（不累积）；序号由后端在库锁内按执行次序生成，旧/重复响应不能回退快照，更新的空状态则清除提示（不误报）；用户关闭后内容不变保持隐藏、变化即重新显示，接近日志上限时删除命令的受限错误文本（含同款恢复指引）经面板错误区展示。控制台继续保留 `warnings`/`cleanupPending` 诊断明细，也不把只读告警态解释为空库。
- **索引损坏后的继续使用（#137，已实现）**：提示脏数据后仍展示可识别的正常资产，允许正常资产的编辑、媒体访问、导入和其他图库操作。下一次成功写入保存可用数据，并先保留损坏索引的原始备份；无法识别的元数据不凭媒体文件猜测。无可恢复条目时同时显示空列表和损坏提示，用户仍可重新导入。备份失败、索引超过大小上限、文件读取失败或删除日志异型等既有阻断条件仍显示错误。恢复范围、原件备份和待核对删除事务的保留规则见 [数据模型 §7.2](data-model.md#72-库资产的分类与编组)。
- **媒体访问（#8、#26、#31）**：桌面端统一按 scope + assetId 获取 `pwmedia` URL，界面不拼接本机媒体路径。浏览器预览导入保有独立 object URL，源库条目删除后缩略图仍可用；浏览器重载不保留该内存映射。
- **流转规则不变**（§7.3）：拖上画布/设为角色头像 = 拷贝进项目（新 id，项目自包含）；项目 → 库「收藏」仍属待实现链路（#29 的保留项）；AI 生成结果先落盘再引用；索引全量内存过滤，媒体懒加载。缩略图读取失败可定位与重试（[issue #142](https://github.com/hailingu/PlotWeave/issues/142)，已实现）：媒体解析失败按资产显示「⚠ 重试」占位（悬停 title 带失败原因），点击重试并成功后清除错误显示图像；其他资产不受影响；观察器回调稳定化（useCallback）+ 在途去重——普通父渲染不反复重建观察器或重发请求，失败态不观察（重试走显式入口）。

前端测试控制原生事件/响应投递顺序，复用真实诊断存储；Rust 验证收集与事件序列化边界。真实桌面事件传输、进程重启与人工清理未端到端执行；监听失败有明确降级，后端发送失败仅记录日志、不重传，跨进程序号仍不比较。没有新增自动删除或持久化格式。恢复本身失败时仍不能得到完整快照，错误照常传播，后续成功诊断再刷新。 异型原生事件沿用记录无效快照日志、保留旧状态的行为，不额外建立会话保护；事件生产者为固定类型 `RecoverySnapshot` 的 Rust 序列化，未发现正常使用或磁盘脏数据产生 null/数组事件的路径。[对应审查](https://github.com/hailingu/PlotWeave/pull/222#discussion_r4052662273) 按仓库 P3 防御增强规则记录、不修改；已有异型事件测试只证明保留与后续更新，不作为通道损坏后安全清理的保证。

### 8.2 设置页

macOS 惯例 ⌘, 打开设置。当前实现为同一主窗口内切换的设置页，关闭后回到原界面；独立设置窗口是目标形态，尚未落地。以下为目标分段组织，当前 provider/模型配置采用数据模型 §10.3 注明的扁平设置，能力目录与三层过滤仍属演进：

- **Provider 分段**：内置适配器列表（OpenAI 兼容 / 火山引擎 Ark / …）+ 自定义 provider。每 provider：Base URL（默认值可覆盖）、API key 状态、模型勾选清单（内置目录 + 自定义条目 + 禁用 = 三层过滤的界面化）。
- **服务地址传输提示**（[issue #136](https://github.com/hailingu/PlotWeave/issues/136)，已实现）：每个 Base URL 输入关联说明「远程服务须使用 HTTPS；HTTP 仅支持回环地址」。存量远程 HTTP 地址仍可查看和编辑，不清空 API key 密文或模型配置；请求时由 Rust 拒绝并显示原因，改用 HTTPS 或本机网关后可重试。局域网明文地址同样拒绝，不提供绕过开关；重定向逐跳复验，HTTPS 不得降级到 HTTP（详见[数据模型 §10.4](data-model.md#104-密钥管理)）。
- **API key 加密后随设置落盘**（修订，不入钥匙串）：Rust 以 AES-256-GCM 加密（密钥绑定本机硬件标识 + 随机盐），密文存 provider 配置的 `keyEnc`；界面只显示「已配置/未配置」，从不回显明文；解密只在 Rust 发起 LLM 请求时进行。防文件明文泄露/跨机器解密，不敌同用户本机恶意程序。
- **读取失败不得降级为默认配置**（[issue #120](https://github.com/hailingu/PlotWeave/issues/120)）：`load_prefs` 仅在 `settings.json` 不存在（首次启动）时返回空对象、由前端补内置默认；文件损坏、超限（>1 MiB）或读取 I/O 失败一律拒绝上抛。设置页在加载完成前不渲染编辑表单（防默认值竞态落盘），失败态展示可见错误与「重试」，原配置文件保持不动，此状态下「完成」直接关闭且不触发任何保存——杜绝以默认值全量覆盖未知的原 provider/模型/密钥密文。只读消费方（AI 面板、图片节点表单、生图作业）读取失败保持空选项/引导态，不落盘。
- **设置保存的成功语义**（[issue #121](https://github.com/hailingu/PlotWeave/issues/121)，已实现）：后端仅在同目录随机排他临时文件写入、文件同步、原子改名与 Unix 父目录同步完成后返回成功；旧固定临时路径占位不再阻断保存。数据目录的创建（首启读取与保存共用内核）在创建时刻同步新目录条目的各级宿主（Unix），创建或同步失败时拆除本次新建层级、重试重新全链同步，返回成功意味着目录条目与文件内容同为持久。改名前失败保留旧文件；改名后目录同步失败仍返回错误，此时完整新版可能已可见，不承诺恢复旧版（[数据模型 §10.2](data-model.md#102-写入安全)）。沿用既有设置页串行保存与关闭重试逻辑，关闭冲刷失败时显示错误并保持页面打开。
- **模型选择分段**：文本/图像/视频的默认模型下拉（三层过滤的计算结果）。
- **无外观设置**：跟随系统外观（第一节原则 1）。

## 九、动效与交互规范

- **响应**：反馈在 pointer-down 即触发，不等释放；拖拽全程 1:1 跟随指针。
- **可中断**：一切动画从当前屏幕值起步、随时可被抓取反向；手势驱动的动画不用 CSS transition/keyframes，用弹簧。
- **速度交接**：手势结束的动画以松手速度为初速度；目标位置用动量投影（`project(v) = (v/1000)·d/(1−d)`，`d≈0.998`）后吸附最近目标。
- **空间一致**：面板从哪进从哪出；弹层以触发元素为变换原点。
- **材质化入场**：玻璃/模糊表面入场时模糊半径与缩放一起动画，而非纯淡入。
- **面板折叠**：无动量场景（面板折叠、卡片显隐）用阻尼 1.0 弹簧；动量交互（甩动等）允许 `damping ~0.8` 回弹。
- **无障碍**：见 §2.6 三变体；动效降级为交叉淡化。

## 十二、macOS 原生质感实现路径（规划）

> 状态：技术选型方向已定，暂不排期实现；待界面质感迭代立项时按 §12.3 顺序落地。本节只约束实现手段，不改变前述各节的设计规格。

### 12.1 已排除方案（选型记录）

- **Framework7（framework7-react）**：为获得类原生观感评估过。它是应用级框架——App/View/Page 外壳、自带路由器与大规模全局样式，与本项目形态正面冲突：外壳是手写状态切换、无路由（§3.1 文档式双界面），画布是 React Flow（页面转场给容器加 transform，与画布缩放/平移坐标系冲突），且其精华是移动端 ios/md 主题，不适配 macOS 桌面窗口。**排除**。若未来出 iOS 版（Tauri 2 支持移动目标），按平台分层另行评审——数据模型与画布逻辑共享，移动壳独立选型，不在本节范围。
- **现成「macOS 风格」CSS 库**（Puppertino 等）：纯 class 驱动、只有视觉层，没有行为层（弹层定位、焦点管理），社区规模与组件覆盖不足以当地基。**排除整库引入**；其样式参数（圆角、阴影、控件规格）可作令牌取值参考。

### 12.2 三层实现路径

「Mac 效果」拆为三层，分别归属 Tauri 配置、无头组件库、设计令牌：

| 层 | 手段 | 要点 |
| --- | --- | --- |
| 窗口级原生质感 | `tauri.conf.json` 的 `windows[].windowEffects`（NSVisualEffectView）+ html/body 透明背景 | 真·窗口毛玻璃，透出窗口后方内容，是内容层 `backdrop-filter` 无法模拟的；Overlay 标题栏与红绿灯安全区已就绪。`prefers-reduced-transparency` 时窗口退化为不透明背景（对齐 §2.6 三变体）。 |
| 交互行为层 | 无头组件库 Radix Primitives（备选 React Aria、Base UI） | 承载弹层碰撞定位、焦点陷阱、Esc/外点关闭、右键菜单、键盘导航——手写最容易出错的部分。零样式自带，不与令牌体系冲突；弹层 portal 到 body，天然避开 React Flow 画布 zoom/transform 的坐标系问题（锚定在节点内部的弹层需 floating-ui 的 transform 处理）。不采用 shadcn/ui——需连带引入 Tailwind，与现有按视图组织的纯 CSS 冲突。 |

### 12.3 落地顺序（立项时执行）

1. `windowEffects` + 透明背景：改动最小，整体观感先达标；
2. 扩展材质与控件令牌，项目首页与设置页先行替换；
3. 弹层类交互（右键菜单、对话框、popover）逐面迁移到无头组件。

引入 Radix 属新增运行时依赖，立项时按仓库规范走独立任务分支与完整验证（`npm run lint && npm run build && npm test`）。
