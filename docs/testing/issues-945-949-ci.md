# PR #952 的 Git 集成测试超时修正

初版 HEAD `bda980bd` 的两次 CI 均只有 `verify-gate-evidence.test.ts` 的“跨合并删除再恢复／保留全部”失败，耗时分别为 6.519s、5.368s，超过默认 5s。其余 4,055 项前端测试以及 Rust、native 和 gate-evidence 通过。

## 调查与修正

该用例把历史播种、恢复提交和普通／发布两次真实核验放在一个测试期限内。本地同版本原样断言通过，Git Trace2 记录 211 次 Git 进程调用；内部 Git 执行总计约 0.484s，最长约 0.017s，整体约 2.78s。CI 差异与进程启动及夹具工作量相符；没有语义断言失败记录，不据此断言托管 runner 的全部耗时来源。

修正复用既有 `gitScenarioFixture`：公共历史仅播种一次，每个模式复制独立完整仓库，不共享可变索引／对象；普通与发布标志分别作为独立用例。所有原有成功、丢失 main、丢失 side 断言保留。默认 5s 测试期限不变；核验子进程另设 30s 硬截止，防止同步子进程长期滞留。生产核验器与门禁判定未修改。

## 验证

- 修正后的完整真实 Git 测试文件：58 项通过，51.98s；两个“保留全部”用例约 1.028s、1.043s。
- 同一受控慢 Git 实验：每次调用真实 `/usr/bin/git` 前只在夹具子进程中延迟 20ms。旧测试耗时 10.669s，按默认 5s 期限失败；恢复修正后的测试后，6 个成功／破坏 × 普通／发布用例全部通过，正例约 3.951s／3.817s，负例约 2.423–2.453s。实验没有提高测试期限，没有跳过真实 Git 或语义断言。
- 旧测试临时替换由 finally 恢复；修正文件 SHA256 `bbfbc679bad3501c5de7a7fec90c2ab627b5b4cdf9ff4b281e4c77b6686d040c` 与备份一致。
