## 中文墨迹测试的有效性

用户随后在同一个独立验证应用中确认：系统默认中文输入法，只有文字顶部裁切，没有候选确认误发送的新反馈。旧的粘贴和同编辑器两行对照不能推翻该结果；#744 保持开放，发布暂停。实际字体诊断得到 TextEditor 使用 Helvetica 12 pt、首字字符框 12 pt，而系统正文为 SFNS 13 pt。字体差异本身尚不等于裁切根因，继续以独立同字体无约束绘制对照排查。首次诊断中把 NSHostingView 加为另一 NSHostingView 子视图收到平台警告，那个参考图无效，已移除，不计作证据。

独立样本使用编辑器同一份字体属性和 2x scale，在留足空间的位图上绘制相同文字。默认 Helvetica 12 下，“连线”实际墨迹 348／独立对照 400，低于保留抗锯齿差异的 90% 下限；“创建，连线”实际高度 22／对照 24 像素，墨迹 763／860，两项失败。“创建”为 21／22 像素和 401／444。完整旧版运行只有这些新对照报告 3 个问题，退出 65，产品源文件尚未修改。

最小产品修正仅为 TextEditor 显式 `.font(.body)`；保留已有顶部内容内边距、尺寸和所有发送／草稿处理。对应运行测得系统正文 13 pt，三个样例实际／独立高度分别为 23／23、23／23、25／25，墨迹 490／513、437／459、935／994，全部通过；原有 72 个两行／单行／长文本对照也通过。这里确认的是隐式 Helvetica 渲染路径的可见字形差异被消除，不推断私有 TextKit 实现，也不单靠这个组件结果关闭用户反馈。 独立字形红灯与绿灯都使用 SDK 27.2，构成同工具链对照；用户实窗的旧应用为 SDK 27.0、新应用为 SDK 27.2，不能把该工具链变化本身当作修复因果证据。修正构建的真实窗口与用户复核另记。

| 新增排查状态 | 必须保持的不变量 | 判定依据 |
| --- | --- | --- |
| 用户系统输入法输入，现有两行草稿 | 保留原草稿；不改 Return／候选／回执所有者 | 用户确认只有顶部裁切；实际 AX 与窗口截图留存工具结果 |

| 后续最小渲染修正 | 单行、多行、宽窄、busy、失焦下文字可见；保留 #832 行为 | 实际窗口复核与公共原生回归，修正后必须重跑最终 HEAD 门禁 |

采样的是 TextEditor 实际缓存位图中字符框上部 45% 的不透明深色像素，并与同编辑器同样文字的第二行比较；90% 比例容差处理行基线和抗锯齿差异，不以声明的内边距作为通过条件。长文本滚到开头后读取首行。测试窗口固定浅色，实际 backingScaleFactor 为 2。

受控实验临时覆盖输入框顶部 16 pt，不改变字符布局；24 组多行对照均因首行墨迹为 0、第二行仍有正值而失败（“创建，连线”对照为 374）。实验覆层已恢复，不属于产品修正，不是用户问题的独立复现，也不报告自动 Swift mutation score。

恢复后 72 组对照全部通过，最小墨迹比例为 0.9665071770。实际全量公共入口 `sh scripts/test-native.sh`：460 tests／97 suites，172.921 秒通过；App 覆盖 9826／10775（91.192575%），79／79 文件，report-only。报告生成于 2026-11-01T13:50:46.841Z。
